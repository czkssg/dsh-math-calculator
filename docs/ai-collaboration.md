# AI 协作：插件给结构，AI 给表达

> 用户的判断（2026-10-25）：
> **情况多种多样穷举不完，所以兜底需要给 AI 注入提示词让 AI 判断，
> 原因结语也可以让模型生产。这些穷举不完的都可以给 AI——
> 这是 AI 的插件，好好利用 AI 的能力。**

## 一、分工原则

| 交给插件（确定性） | 交给 AI（生成性） |
|---|---|
| 数值计算、量纲检查 | 结语怎么写 |
| 硬约束是否成立 | 这个设定合不合理（叙事判断） |
| 区间与概率云 | 该选哪个方案 |
| 结构化的判定结果 | 把结果变成读者能读懂的描述 |

**插件不做的事**：不用枚举所有情况的结语。给结构、判据、少量参考写法，AI 生成。

## 二、结语改为「参考写法」

`FatalCause.epitaph` 现在是**可选字段**，注释里写明：

> 定性结语的**范例**（不是唯一答案）。
> 插件只给结构化的物理事实，具体怎么写交给 AI 与用户。
> 这里的句子是「可以这样写」的参考，AI 完全可以另写。

渲染时的标签也从「定性结语」改成「**参考写法**」。

## 三、`dead` 子命令现在输出两段

### 第一段：结构化事实（插件算的）

```
【致命原因】
  · 全球冻结（180 K，冰点 273 K）
    物理依据：地表均温低于溶剂冰点，没有液态介质
    参考写法：海洋是一整块冰，化学反应只能以极慢的固相扩散进行。
    若想要物质世界：提高温室效应、拉近轨道、或提高恒星光度
```

### 第二段：给 AI 的提示（判断权移交）

```
─── 给 AI 的提示（插件不做穷举，以下由你判断）───
【世界状态判定：dead】

结构性事实（插件算出的，可直接引用）：
- 全球冻结：180 K（冰点 273 K）
  物理依据：地表均温低于溶剂冰点，没有液态介质

关键参数：地表均温_K=179.8, 重力_m/s2=9.82, 气压_atm=1, 恒星寿命_Gyr=10

参数调整方向（仅供参考，不是唯一解）：
- 提高温室效应、拉近轨道、或提高恒星光度

你的任务（AI）：
1. 用一段有画面感的文字描述这个世界的状态——要写成读者能读懂的，
   不要照抄上面的物理术语。
2. 如果用户想要的是别的效果，指出该调哪几个参数、朝哪个方向。
3. 如果用户就是想要这样的世界，把它当作设定来写，不要说「这不合理」。
```

## 四、注入到系统提示的三段话

### brief 档（默认）

```
**分工**（重要）：插件只给结构与判据，不做穷举。
· 该算的（数值/判定/区间）调工具，引用它的结果；
· 该写的（结语/描写/把数字译成读者能懂的话）由你生成，不要照抄工具的输出；
· 插件给的是「参考写法」不是唯一答案；用户的设定由用户决定，不要反驳。
· 算不出来的别编数字——去问用户，或标为待定。
```

### full 档

额外列出全部 `derivation` 子命令与 `custom`，并强调：

```
- **插件不做穷举**：它给结构、判据、少量参考写法；
  具体的结语、描写、叙事判断由你生成，别照抄工具输出。
- **不要反驳用户的设定**：插件指出「按这个参数会怎样」，
  由你转述给用户，并给出「想保留的话可以怎么调」的选项。
```

## 五、新增两个提示词构建器

| 函数 | 用途 |
|---|---|
| `buildCapabilityPrompt()` | 告诉 AI 哪些该算、哪些该写 |
| `buildAskUserPrompt()` | 什么时候该问用户而不是硬算 |

`buildAskUserPrompt` 的内容：

```
【何时该问用户，而不是硬算】
插件算不出来的，别编数字，去问：
  · 这是给读者看的硬设定，还是背景板？（决定精度）
  · 观测者是谁？（会影响全部体感结论）
  · 哪些是「必须成立」的叙事锚点，哪些可以妥协？
  · 这个世界你更想要哪种张力？
问法则：一次问 1-2 个，别列问卷。先给出你算出的东西，再问。
```
