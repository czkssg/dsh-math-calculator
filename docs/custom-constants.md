# 自创常数与新物理量

> 用户提出的关键需求：**有些设定靠调现有参数怎么都做不出来**，必须引入
> 「新物理量 / 新规律 / 新物质」（比如以太、灵能、超材料）。
> 所以常数表与公式库都必须可扩展。

## 一、现状盘点（哪些本来就能扩）

| 能力 | 状态 | 位置 |
|---|---|---|
| 公式可扩展（本区） | ✅ 已有 | `formulaTable.custom` |
| 公式可扩展（全局） | ✅ 已有 | `formula-packs/global.json` |
| 常数覆盖 | ✅ 已有 | `workspace.constants`（但只能改**已有**常数） |
| **自创新常数** | ❌ **缺失** | ← 本次补上 |

## 二、新增：自创常数（带量纲强制）

```jsonc
{
  "operation": "custom", "customAction": "add",
  "customConstant": {
    "name": "aetherPressure", "label": "以太压",
    "value": 1.2e6, "unit": "Pa",
    "meaning": "决定这个世界能否超光速通信",
    "dimension": { "M": 1, "L": -1, "T": -2 },
    "origin": "author"
  }
}
```

### 为什么强制量纲

这是**自适应的第一道闸**。没有量纲，公式会悄悄算错，等推演跑完才发现结果离谱。
现在定义时缺量纲直接被拒：

```
✗ 缺少 dimension（量纲）——不做量纲检查的话，公式会悄悄算错
```

### 两种来源

| origin | 含义 | 例子 |
|---|---|---|
| `author` | 作者直接设定 | 以太压 = 1.2e6 Pa |
| `derived` | 由其它量推出 | 灵能密度 = 以太压 × 1e-8 × c |

派生量**按依赖自动求解**（多轮拓扑，最多 5 轮），实测：

```
aetherPressure（以太压）  = 1.200e+6 Pa
psiDensity（灵能密度）    = 3.598e+6 J/m³   ← 自动算出
```

## 三、量纲检查（自创公式的发行前自检）

```jsonc
{"operation":"custom","customAction":"check","expression":"aetherPressure * length^3",
 "expectedDimension":{"M":1,"L":2,"T":-2}}
```

实测结果：

| 表达式 | 期望 | 判定 |
|---|---|---|
| `aetherPressure * length^3` | 能量 | ✓ 一致（压力×体积=能量） |
| `aetherPressure * mass` | 能量 | ✗ 不一致 |

**不给期望量纲时不会假装通过**，而是：

```
⚠ 未指定期望量纲，无法判定对错。
结果量纲 L^2·M·T^-2 对照常见量：
  → 这看起来是「能量」
```

## 四、安全求值器（派生量用的）

不用 mathjs，避免依赖膨胀与注入风险。白名单：

- 只允许数字、已知量名、`+ - * / ^`、括号、空格
- 未知变量直接报错
- 函数调用、分号、`alert` 之类全部拒绝

### 踩到的坑：科学计数法

`1e-8` 里的 `e` 曾被当成变量名，报「未知量 e」。

修正过程记录：
1. 第一版用占位符 `#EXP#` → 占位符里的字母又成了「未知量 EXP」；
2. 最终改为**整体替换成纯小数**（`1e-8` → `0.00000001`），
   且必须用 `toFixed(20)` 而非 `String()`——因为 `String(1e-8)` 仍是 `'1e-8'`。

## 五、接入点

| 位置 | 能力 |
|---|---|
| `operation=custom` | list / add / remove / check |
| `GET /custom-constants` | 列出本区自创量（含当前求解值） |

## 六、关于"自流水线"与自适应

用户提到：能不能把自创 → 推导 → 判定做成自流水线？
**可以，但自适应必须靠这三道闸**：

1. **量纲闸**（已实现）：定义时就要求量纲，公式写错立刻能查出来；
2. **区间闸**（已实现）：接口卡有允许/边缘/禁止区间，新量代入后照样判定；
3. **派生闸**（已实现）：derived 量必须有依赖与表达式，依赖缺失会显式报错。

**没有这三道闸的"自适应"是危险的**：AI 自创一个量、自创一条公式，
插件照算不误，结果可能完全脱离作者意图。有了闸，至少能保证
「量纲对不上」「依赖不存在」这类硬错误当场暴露。
