# 幻想层：算清现实量，只提醒不反驳

> 定位（用户 2026-10-25 明确）：**插件是给用户圆世界观的，不是去反驳的。**
> 幻想怎么设定由用户与 AI 交互决定；插件只负责算的时候别忘结合幻想量与真实量，
> 检查逻辑自洽，提个醒。

## 一、之前的设计偏差

第一版把幻想层做成了**判定器**：效率 > 1 判「禁止」、无代价拒绝定义、超预算判「边缘」。
这是错的——它变成了审查器，而不是帮助作者圆世界观的工具。

现在改成**提醒器**：只算数字 + 给建议，措辞一律是「如果不打算改，可以设想……」。

## 二、现在做什么

### 1. 叠加（不覆盖）

```
有效能力 = 物理能力 + 幻想能力
幻想能量 = (需求 − 物理能力) / 效率
总代价   = 幻想能量 × 单位成本
```

实测（法师 5kW，效率 0.5）：

```
需求总量  5000
物理提供  100     ← 保留，没被覆盖
幻想补足  4900
合计      5000
```

### 2. 换算成等价现实量（这才叫「结合幻想与真实」）

```
等价人力  49.0 人       ← 按 100W 持续输出
等价食物  3.06e-4 kg 糖/秒
散热需求  49.00 m²      ← 按 100W/m²
```

### 3. 提醒（不是判定）

三种情况的实际措辞：

| 情况 | 现在怎么说 |
|---|---|
| 超预算 | 「若不打算改，可以让施法有冷却/蓄力时间来覆盖这个缺口」 |
| 散热不足 | 「若不打算改热功率，可以设想他有散热手段（汗腺强化、水冷外衣、短时爆发）」 |
| 温升很高 | 「这本身可以当作设定亮点：强力施术者都会烧起来，读者会觉得可信」 |
| 效率 > 1 | 「这属于额外能量源的设定，故事里通常会交代它从哪来（信仰、地脉、外部文明）」 |
| 无代价 | 「读者可能会问那为什么不是人人都会。想圆的话可以给个非能量代价，或干脆设定为人人都能」 |

**输出里没有「禁止」和「必须」这两个词**（有专门测试守着）。

## 三、实测对比

| 案例 | 旧版 | 新版 |
|---|---|---|
| 法师 5kW | 判「边缘」 | 数字 + 「可以设想他有散热手段」 |
| 效率 3 倍 | 判「禁止」 | 「这属于额外能量源的设定，通常会交代它从哪来」 |
| 无代价魔法 | 拒绝定义 | 「想圆的话可以给个非能量代价，或设定为人人都能」 |

## 四、唯一保留的拦截：算不出来

字段缺失导致算不了，这不是世界观判断：

```
缺 name / 缺 label / efficiency <= 0 / powerLimit <= 0
```

`efficiency > 1`、`costPerUnit = 0` 都**不拦**——它们算得出来，只是会提醒。

## 五、与流水线的关系

幻想层**不纳入 pipeline**（用户决定：留给 AI 与用户交互裁决）。
它作为一个独立子命令 `derivation="fantasy"` 提供计算与提醒，
AI 在需要的时候调用它算一把，然后自行判断怎么用。

## 六、用法

```jsonc
{"operation":"derivation","derivation":"fantasy",
 "fantasyAbility":{
   "name":"psiOutput","label":"灵能输出","source":"metabolism",
   "efficiency":0.5,"costPerUnit":1,"powerLimit":8000,
   "boosts":"体力","meaning":"法师靠代谢转化灵能"},
 "fantasyDemand":5000,"fantasyPhysical":100,"fantasyBodyArea":1.8}
```

## 七、验证

```
48 套 / 1981 项全绿（fantasy.mjs 36 项）
叠加式：total = 物理 + 幻想 ✓
等价现实量：人力/食物/散热/温升都能算 ✓
不反驳：输出无「禁止」「必须」字样 ✓（有测试守着）
字段检查：只拦算不了的，不拦设定 ✓
```
