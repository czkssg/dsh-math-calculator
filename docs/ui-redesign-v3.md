# UI 方案 v3：参数分层与自洽推演

> 状态：**设计方案，未实现**
> 依据用户反馈：精简方向对，但四个参数选错了——那不是基础参数；
> 且**不能硬设定**，必须背后有函数支撑，改任何一项都要在整个体系里体现出来。

## 一、上一版方案的错误

我上一版把界面输入定为「重力、一天、轨道、均温」——
**这四个里，重力、一天、均温都是派生量**：

| 我说的输入 | 实际是什么 | 由谁决定 |
|---|---|---|
| 重力 | **派生** | `g = G·M/R²` ← 质量 + 半径 |
| 一天 | 半派生 | `rotationHours`，但「太阳日」还要按公转折算 |
| 均温 | **派生** | 轨道 + 反照率 + 温室 + 恒星 |
| 轨道 | 基础 ✓ | 可直接输入 |

**如果界面直接让用户填「重力 = 1.5」，后台该怎么办？**

两种做法都不对：

| 做法 | 后果 |
|---|---|
| 把重力当输入存下来 | 与 `G·M/R²` 冲突。改了质量忘了同步重力，世界自相矛盾 |
| 把重力当只读显示 | 用户想调重力却没有入口，只能自己猜质量 |

## 二、关键验证：反解是可行的

我实测了「锁定派生量、反求基础量」这条路：

```
诉求：我要 1.5 倍重力，半径保持 1
反解：M = g_target × R² = 1.5 × 1² = 1.5 地球质量
验证：实际重力 = 1.502 g   ✓ 对上了
连带：大气标高自动从 8399 m → 5600 m（因为重力变了）
```

**结论：反解 + 全部重算是可行的，而且连带效应会自动传导。**

这就是「不硬设定、有函数支撑」的具体实现方式。

## 三、参数分层的三层结构

### 第 1 层：物理基础量（真正独立，可直接输入）

这些量**不依赖其他输入**，改了它们，下游一切重算。

| 类别 | 参数 | 单位 | 说明 |
|---|---|---|---|
| 恒星 | `starClass` | 光谱型 | ★ 优先：选「G2V」自动填质量/半径/温度 |
| 恒星 | `starMass` | 太阳质量 | 决定寿命与光度（M^4） |
| 恒星 | `starTemp` | K | 决定光谱与宜居带颜色 |
| 轨道 | `orbitAU` | AU | 决定冷暖与年长 |
| 轨道 | `eccentricity` | 0—1 | 决定季节幅度 |
| 行星 | `planetMass` | 地球质量 | → 重力、逃逸、大气保留 |
| 行星 | `planetRadius` | 地球半径 | → 重力、表面积 |
| 行星 | `rotationHours` | 小时 | → 昼夜、科氏力、风暴 |
| 行星 | `obliquityDeg` | 度 | → 季节强度 |
| 行星 | `albedo` | 0—1 | → 均温 |
| 大气 | `pressure` | Pa | → 沸点、呼吸、飞行 |
| 大气 | `greenhouse` | K | → 均温（温室增温） |
| 大气 | `molarMass` | kg/mol | → 声速、标高 |
| 材料 | `materialStrength` | Pa | → 建筑上限 |
| 材料 | `materialDensity` | kg/m³ | → 建筑上限 |

**共 15 个**（实际界面只展示高频的几个，其余收在「更多」）。

### 第 2 层：派生量（只读，由第 1 层算出）

| 派生量 | 公式 | 依赖 |
|---|---|---|
| 表面重力 | `g = G·M/R²` | 质量、半径 |
| 逃逸速度 | `v = √(2gR)` | 重力、半径 |
| 一天（太阳日） | `rotationHours` + 公转折算 | 自转、轨道 |
| 年均温 | 辐射平衡 + 温室 | 轨道、反照率、温室、恒星 |
| 大气标高 | `H = kT/(μg)` | 温度、重力、摩尔质量 |
| 恒星寿命 | `τ ∝ M^-2.5` | 恒星质量 |
| 宜居带 | `r ∝ √L` | 恒星光度、温度 |
| 建筑高度上限 | `σ/(ρg)` | 材料强度、密度、重力 |

### 第 3 层：叙事锚点（用户要的「目标」，可反解）

这一层**不是物理量**，是作者的语言：

```
「我要 50 米高的巨兽」
「我要能飞出这个行星」
「我要一年有四个明显的季节」
```

每个锚点绑一个**反解器**（已有 `backSolve`），从第 3 层反推第 1 层。

## 四、界面怎么体现这个分层

### 主区：三段式

```
╔══════════════════════════════════════════════════════════════╗
║ 《工作区》          已绑定 · 18:42              [导出设定]      ║
╠═══════════════════════╦══════════════════════════════════════╣
║ ① 设定这个世界（可调）  ║ ② 这个世界长什么样（派生）             ║
║                       ║                                      ║
║ 恒星  [G2V ▾]         ║   重力        9.8 m/s²（1.0 g）       ║
║ 离恒星 [ 1.0 ] AU      ║   逃逸速度    11.2 km/s              ║
║ 行星质量 [ 1.0 ] M⊕   ║   一天        23.9 小时               ║
║ 行星半径 [ 1.0 ] R⊕   ║   年均温      287 K                   ║
║ 一天   [24.0 ] 小时    ║   年长        365 天                  ║
║ 轴倾角 [23.4 ] 度      ║   大气标高    8399 m                  ║
║                       ║                                      ║
║ ▸ 更多参数（展开）     ║ ③ 这意味着什么                       ║
║   大气压 / 温室 / ...  ║   ‖ 生物                              ║
║                       ║     身高上限 25 米                    ║
║ ─────────────────     ║   ‖ 文明                              ║
║ ④ 我想要（反解）       ║     化学火箭 ✓ 能飞出                 ║
║ 重力要 [1.5] 倍        ║   ‖ 能不能住                          ║
║ → 质量需 [1.5] M⊕      ║     ✓ 可以住人                        ║
╚═══════════════════════╩══════════════════════════════════════╝
```

**四个区块，全部一屏可见，无导航。**

| 区块 | 性质 | 交互 |
|---|---|---|
| ① 设定这个世界 | 基础量（可写） | 输入 → 自动存 → 全量重算 |
| ② 这个世界长什么样 | 派生量（只读） | 随 ① 实时更新 |
| ③ 这意味着什么 | 推演结论 | 随 ① 实时更新 |
| ④ 我想要（反解） | 叙事锚点 | 填目标 → 反解出 ① 的值 → 一键应用 |

### ④ 反解区是核心创新

这是「不硬设定、有函数支撑」的界面表达：

```
┌─ 我想要 ─────────────────────────────┐
│ 重力要  [ 1.5 ] 倍地球                │
│                                      │
│ → 需要把行星质量调到 1.50 M⊕          │
│   （半径保持 1.0 R⊕）                 │
│   连带：大气标高 8399 → 5600 m        │
│        逃逸速度 11.2 → 13.7 km/s      │
│                                      │
│            [ 应用这个改动 ]            │
└──────────────────────────────────────┘
```

**用户只需要说「我要什么」，界面上立即显示「那得改哪个基础量、还有什么连带效应」。**

这比让用户填 `planetMass = 1.5` 好得多——后者要求用户懂物理。

## 五、显示什么参数（高频优先）

① 区默认显示 6 个，其余收在「更多参数」里：

| 默认显示 | 理由 |
|---|---|
| 恒星类型 | 一个下拉选完，比填 3 个数字友好 |
| 离恒星多远 | 决定冷暖，作者一定关心 |
| 行星质量 | 决定重力，最常调 |
| 行星半径 | 和质一起决定重力 |
| 一天多长 | 决定昼夜与风暴 |
| 轴倾角 | 决定有没有四季 |

| 收起（点「更多参数」展开） |
|---|---|
| 大气压、温室效应、摩尔质量、绝热指数 |
| 反照率、轨道偏心率 |
| 材料强度、密度 |
| 卫星数量/质量/距离 |

## 六、自洽性如何保证（技术方案）

### 规则 1：派生量绝不入库

```
WorkspaceData.world 里只存基础量（15 个白名单）
重力、均温、一天… 永远现算，不存
→ 不可能出现「存的重力与公式算出的重力不一致」
```

### 规则 2：每次改动都全量重算

```
输入变化 → 300ms 防抖 → world 全量重算 → pipeline → civilization → 综合
实测总耗时 2.1 ms，完全够实时
```

### 规则 3：反解只改基础量

```
用户说「我要 1.5g」
→ backSolve 解出 planetMass = 1.5
→ 写入 world.planetMass（不是写重力）
→ 界面显示新值，用户可再手改
```

### 规则 4：矛盾要提示，不静默

```
若同时给了 starClass 和 starMass：显示「你用 G2V，但我们按你填的 1.2 M☉ 算」
若参数组合不可住：右侧横幅说明「太冷，海洋冻住——想改就拉近轨道」
```

## 八、这次改动的验收标准

| # | 标准 | 验证方法 |
|---|---|---|
| 1 | 界面输入全是基础量，无派生量 | 代码检查 + 测试 |
| 2 | 改任一基础量，②③ 全部更新 | 改质量 → 重力/逃逸/标高/建筑全变 |
| 3 | 反解可用 | 填「1.5g」→ 解出 1.5 M⊕ 并应用 |
| 4 | 不存在「存的重力与算的重力不一致」 | 数据里根本没有重力字段 |
| 5 | 矛盾有提示 | 同时给 starClass 与 starMass 时提示 |
| 6 | 一屏完成 | 无导航、无跳页 |

## 九、仍需你确认

1. **① 区默认 6 个参数够吗？**
   恒星类型、轨道、质量、半径、日长、轴倾角。
   要不要把「大气压」也提到默认？（它决定能不能呼吸、水会不会沸腾）

2. **④ 反解区放哪几个锚点？**
   我建议先做 3 个：`要几倍重力` / `要能飞出` / `要生物能长多高`。
   后端 `backSolve` 已支持 creatureHeight 等 4 个，可扩展。

3. **「更多参数」里 9 个要不要全放？**
   我建议只放：大气压、温室、反照率、偏心率 4 个。
   材料强度/密度对作者太专业，留给 AI。
