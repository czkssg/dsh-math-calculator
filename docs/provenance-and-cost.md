# 补丁4/5：因果溯源 + 算力预警

## 一、补丁4 因果溯源

> 方案原文：点击任一宏观节点，逆向高亮其底层依赖路径（面包屑导航），
> 解决节点爆炸时的迷失问题。

### 解决什么问题

用户看到「建筑高度上限 4903 米」，会问 **这个数怎么来的？**
没有溯源，他只能看到一个孤立数字；有了溯源，他知道该改哪一项。

### 实测

```jsonc
{"operation":"derivation","derivation":"trace","traceTarget":"建筑高度上限"}
```

```
═══ 因果溯源：建筑高度上限 ═══

【依赖链】（越往下越基础）
  ● 建筑高度上限
    ← 表面重力
      ← 行星质量, 行星半径

【最终落到的基础量】行星质量, 行星半径

【想改变「建筑高度上限」，最该动这些】行星质量, 行星半径
```

### 依赖图的四类边（104 条，76 个节点）

| 类型 | 数量来源 | 例子 |
|---|---|---|
| `constant` | 常数图 | `hbar ← h` |
| `P1`—`P5` | 接口卡 | `骨骼强度体重比 ← 材料强度密度比, g` |
| `constraint` | 可行性约束 | `建筑高度上限 ← 表面重力` |
| `bridge` | 桥接边 | `表面重力 ← 行星质量, 行星半径` |

**桥接边是关键**：没有它，溯源会停在「表面重力」这种中间概念上——
用户知道「建筑上限依赖重力」，但还是不知道该改什么。

### 反向：影响面

```jsonc
{"operation":"derivation","derivation":"impact","traceTarget":"c"}
```

```
【直接依赖 c 的】11 项
  mu0, sigma, bWien, alpha_fs, ly, mPlanck, lPlanck, tPlanck, re, alphaG, 键能范围

【间接波及的】8 项
  Lsun, 辐射谱峰值波长, 主要溶剂相变点, 辐射吸收窗口,
  材料强度密度比, 代谢能尺度, 热导与散热, 骨骼强度体重比

改之前先看这个清单——波及面越大，越需要重新校验。
```

**改一个光速，会一路波及到骨骼强度**——这就是跨层传导的具体样子。

## 二、补丁5 算力预警

> 方案原文：若判定某一高精度全域切片计算耗时超限，强制弹窗警告，
> 并提供降级计算（自适应网格采样）选项。

### 解决什么问题

用户点「相图 200×200」时不知道这要算 24 秒——点下去就卡住。

### 实测

```jsonc
{"operation":"derivation","derivation":"cost","costKind":"phase","costX":200,"costY":200}
```

```
═══ 算力估算：相图 (200×200) ═══

  计算单元：1.20e+6
  估算耗时：24.0 秒
  估算内存：19.53 MB
  风险等级：很慢

  会算很久（超过 15 秒）。强烈建议降级，或者接受等待。

【降级建议】
  · 减少采样点数（约减半）     约省 50% 时间；代价：曲线会更粗糙
  · 只算关心区间（缩小范围）   按范围比例省时间；代价：看不到全貌
  · 先粗扫再精算（两阶段）     通常省 70—90%；代价：多一次交互
```

### 踩到的坑：系数低估

第一版 `UNIT_COST_MS = 0.02`，把 1000 步时间轴估成 **0.4 秒**——实际是秒级。

改成 **0.2** 后，1000 步估到 4 秒。

**原则：宁可高估也不要低估**——低估会让人以为可以随便跑，然后卡在半路。

### 风险分级

| 等级 | 阈值 | 说明 |
|---|---|---|
| `fast` | < 0.5 秒 | 直接算 |
| `moderate` | 0.5—3 秒 | 可以接受 |
| `slow` | 3—15 秒 | 建议先估是否值得 |
| `very-slow` | > 15 秒 | 强烈建议降级 |

### 定位：不拒绝，只提醒

```
说明：这些是估算值（经验系数），实际耗时会有波动。
插件不会拒绝你的请求，只是让你知道代价。
```
