# 顶层架构：确定性底座 + AI 开放层

> 用户 2026-10-25 定稿的顶层设计原则：
>
> **确定性部分**：基础计算模块、常数表、公式库、可枚举的硬规则。
> **AI 部分**：情况判断、兜底处理、原因生成、结语生成，以及所有「穷举不完、列不完」的开放边界。
> **插件本体**：不是写死分支逻辑，而是给 AI 注入一套推演提示词/指令集，
> 让它调用底座能力做判断和生成。

## 一、这个架构解决什么问题

写死分支的老路：

```
if (情况A) 结语A
else if (情况B) 结语B
...
```

问题：世界的可能性是无穷的。第 28 种情况永远有人能想出来，插件永远追不上。

**新架构**：

```
确定性底座（算得准）
    ↓
推演指令集（告诉 AI 有什么、怎么用、边界在哪）
    ↓
AI 开放层（判断与生成）
```

## 二、`playbook.ts` 的四块内容

### 1. 底座能力清单（12 项）

每项都说明：**调用方式 / 产出什么 / 何时用 / 不管什么**

| 能力 | 产出 | 不管 |
|---|---|---|
| `evaluate/solve/matrix/stats` | 数值与可信度标签 | 不解释数字的意义 |
| `formula/formulas`（355 条） | 带适用域的公式求值 | 不判断值在故事里合不合适 |
| `world` | 星球画像/天空/恒星/卫星/生命闸门 | 不写文化历史 |
| `derivation → pipeline` | P1—P5 逐层判定 | 不说该改哪一层 |
| `derivation → backSolve` | 从锚点反推参数窗口 | 不判断诉求是否值得保留 |
| `derivation → civilization` | 能量/材料/交通/技术树极限 | 不写社会形态 |
| `derivation → observer` | 体感重算与能力过滤 | 不判断该有什么文化 |
| `derivation → dead` | 死寂判定结构化原因 | **不生成结语** |
| `derivation → chaos` | Lyapunov 判定与概率云 | 不给确定数值 |
| `derivation → fantasy` | 幻想量的等价现实量 | 不判断设定合不合理 |
| `custom` | 自创量定义与量纲校验 | 不判断是否说得通 |
| `archive/history/compare` | 七张表与版本差异 | 不判断哪个版本更好 |

### 2. AI 职责清单（6 项）

每项都说明：**职责 / 为什么插件不做 / 做好是什么样**

| 职责 | 为什么插件不做 |
|---|---|
| 把数字译成读者能懂的话 | 同一个 1.6g，可以是压迫感、异星感、或「这里的人都很矮」——语境决定 |
| 生成结语 / 定性描述 | 穷举不完，每换一种死法都该有新写法 |
| 判断设定在叙事上合不合适 | 这是价值判断，插件没有立场 |
| 在多个方案里挑一个 | 插件不知道用户更在乎什么 |
| 兜底：插件没覆盖的情况 | 世界可能性无穷，规则集必然不全 |
| 问对问题 | 关键信息只有用户知道 |

### 3. 判据分级

| 类别 | 内容 |
|---|---|
| 硬约束 | 原子无法稳定、没有液态介质、恒星寿命不足、违反能量守恒、量纲不自洽 |
| 软约束 | 生物形态、材料选择、城市尺度、技术路径被锁死（可换路径） |
| 叙事选择 | 要有巨兽、要有长寿命文明、要有灵能、要有特定社会形态 |

冲突优先级：**硬约束 > 核心叙事锚点 > 软约束 > 细节设定**

### 4. 工作流（11 步，按需跳步）

每步标注「跳过条件」，例如：

| 步骤 | 做法 | 跳过条件 |
|---|---|---|
| 4 硬约束筛选 | `pipeline` / `dead` 排除禁区 | **绝不跳过** |
| 6 正向推演 | `pipeline` P1→P5 | **绝不跳过** |
| 7 逆推校准 | `backSolve` 从锚点反推 | 有「必须有」的诉求时才用 |
| 8 敏感性 | `sensitivity` / `phase` | 参数接近边界时才需要 |

## 三、关键：指令集是**动态定制**的

不是固定模板，而是按工作区实际状态生成。实测：

**空白工作区**（5 行）：

```
**世界推演：底座算数，你判断与表达。**
- 该算的调 `derivation`（pipeline/civilization/dead/observer/backSolve/chaos）与 `custom`
- 该写的（结语、描写、叙事判断）由你生成，别照抄工具输出
- 硬约束（物质不存在等）如实说；叙事选择（要巨兽、要灵能）不反驳，只讲代价
- 算不出来的别编，标待定或问用户
```

**改过常数 + 有自创量**（自动追加 2 条）：

```
- 本区改过常数，先跑 dimensionless 确认不是单位重定义
- 本区有自创量，它们与现有物理的关系要你判断
```

**有推演档案**时还会再追加：

```
- 本区已有推演档案：改完参数可调 compare 看前后差异，并把「哪些判定翻转了」讲给用户
```

## 四、注入位置

| 档位 | 注入内容 | 规模 |
|---|---|---|
| `brief`（默认） | `buildBriefPlaybook`：5 行核心指令 | ~250 字 |
| `full` | `buildPlaybook`：底座清单 + AI 职责 + 判据 + 工作流 + 底线 | ~80 行 |
| `off` | 不注入 | — |

## 五、两条底线（写进每一档）

1. **不要反驳用户的设定。** 插件指出「按这个参数会怎样」，AI 转述，并给出「想保留的话可以怎么调」。
2. **不要编数字。** 算不出来的标待定或问用户。
