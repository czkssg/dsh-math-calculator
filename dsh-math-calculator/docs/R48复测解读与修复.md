# R48 复测解读与修复（2026-11-16 23:30）

## 一、先说结论：报告里的「5 项失败」其实只有 1 个真缺陷

我在当前构建下逐条复现 R48 的失败项：

| 项 | R48 报告 | 我复现的结果 |
|---|---|---|
| ledger | `THROW: value is not lossless JSON` | **ok，但 value 里含 undefined**（根因） |
| eigen | `[object Object]` | **正常**：`[3, 1]` |
| system | `[object Object]` | **正常**：`{solution:[2,1],rank:2,unique:true}` |
| recurrence | `[object Object]` | **正常**：5 期表 |
| chain | `[object Object]` | **正常**：传导表 |

**关键发现**：`[object Object]` 不是独立的 5 个错误，而是**同一个根因的次生现象**——
宿主 `snapshotJsonValue` 校验失败后抛出 `ToolOutputError`，错误对象再被 `String()` 化就成了 `[object Object]`。

## 二、根因：value 里不能有 undefined

宿主 dsh-tools 的输出校验：

```js
function snapshotToolValue(toolName, candidate) {
  const detached = snapshotJsonValue(candidate);
  if (detached === void 0) throw new ToolOutputError(toolName, ['value is not lossless JSON']);
}
```

**只要 value 里任何一个属性是 undefined，整个输出被判非法。**

### 具体触发点

| 文件 | 写法 | 问题 |
|---|---|---|
| `features/graph/ledger.ts:111` | `parts.push({ name, value, note: part.note })` | note 缺省时是 undefined |
| `dispatch.ts:244` | `value: { ...result, ascii: undefined }` | 想剔除字段，反而造出非法值 |

## 三、修法：出口统一清理（不是在 60 个 op 里各修一次）

在 `mathExecuteTool.execute` 的出口加：

```js
if (result.value !== undefined) {
  result = { ...result, value: stripUndefined(result.value) }
}
```

`stripUndefined` 递归删掉值为 undefined 的键（数组里的转 null）。

**为什么在出口修**：这是宿主契约问题，不是某个 op 的问题。60 多个 op 里任何一个将来
再写出 `{ a: maybeUndefined }` 都会复发；出口清理是一次性的。

## 四、验证（新增守护测试 output-lossless）

**8 项**，核心是复刻宿主的判定：

function findBad(value) { /* undefined / NaN / Infinity / function / 循环引用 */ }

覆盖：ledger 简化与显式两种写法、批量求值、world-map（给/不给 ascii）、10 个主流 op 抽样。
