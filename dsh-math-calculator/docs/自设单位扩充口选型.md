# 自设单位扩充口·选型记录

> 按用户铁律「开工前先查开源社区」，本文记录查证过程与选型理由。
> 用户需求（2026-11-12）：**给单位体系尝试一个自设扩充口**。

## 一、查到了什么

| 源 | 内容 | 判断 |
|---|---|---|
| [Extending UCUM?（Grahame Grieve, 2025-01）](https://www.healthintersections.com.au/2025/01/14/extending-ucum.html) | UCUM 官方扩展思路：用 `@` / `$` 前缀隔离命名空间 | **★ 采用其设计原则** |
| [UCUM Requests for Units](https://ucum.org/docs/requests) | 官方「申请新单位」流程 | 参考其治理要求 |
| `mathjs` 的 `createUnit` | 支持 `{definition, aliases, prefix, offset}` | **★ 实现基础** |
| `@lhncbc/ucum-lhc` | 只支持标准 UCUM，无扩展机制 | 不适用 |
| QUDT | 有 `qudt:Unit` 但无「用户自定义」层 | 不适用 |

**结论：没有现成的「用户自定义单位」库可引。** 但 UCUM 社区的扩展讨论给出了成熟的设计原则。

## 二、从 UCUM 扩展讨论中采纳的四条原则

### ① 命名空间隔离（最重要）

原文：

> prefixes all the units it defines with either `$` (for currencies) or `@` for countable units.
> These are legal unit codes in UCUM, but no existing UCUM codes use either character

**采纳**：自设单位统一加 `x_` 前缀（mathjs 只允许字母数字，用不了 `@`），
并在**显示层**还原成 `@名字`，让人一眼看出「这不是标准单位」。

### ② 不得用于定义真实单位

原文：

> it wouldn't be used to define real units

**采纳**：注册时检查 —— 若自设单位与已有单位同名或同量纲同值，
**拒绝注册并提示改用已有单位**。这条能防止「同一个东西两个名字」的碎片化。

### ③ 必须能参与标准单位的运算

原文：

> it would allow mixing the arbitary units with real UCUM units using the existing UCUM grammar

**采纳**：自设单位注册进 mathjs 后天然满足（`1 x_船速 + 3 m/s` 能算）。

### ④ 库必须能识别「这是非标准单位」

原文：

> a UCUM library wouldn't accidentally mis-understand an extended UCUM expression,
> it would identify that it contained a non-ucum unit

**采纳**：查询接口区分「内置 / 时代 / 自设」三类，
输出时自设单位带 `[@名]` 标记。

## 三、为什么自设单位必须存储而不是仅注册

mathjs 的 `createUnit` 只在**进程内**生效。而本插件的使用场景是：

```
第 1 轮  作者定义「1 维尔 = 1.2 km」（他世界观里的长度单位）
第 2 轮  另一个调用要用「5 维尔」
```

若只注册不存储，第 2 轮就找不到。

**所以自设单位要落盘**，与老插件的「工作区」机制一致。

---

## 四、存储设计

### 4.1 放在哪

```
<数据目录>/custom-units.json     ← 全局层（跨工作区）
<数据目录>/workspaces/<名>.json  ← 工作区层（含 units 字段）
```

两层的原因：一个世界观里的「维尔」不该污染另一个世界观。

### 4.2 存什么

```json
{
  "version": 1,
  "units": [
    {
      "name": "weiEr",
      "display": "维尔",
      "dimension": "length",
      "factor": 1200,
      "baseUnit": "m",
      "note": "本世界长度单位，1 维尔 = 1.2 km",
      "createdAt": "2026-11-12T23:50:00+08:00"
    }
  ]
}
```

**必须存 `dimension` 与 `factor`**，而不只存 `definition` 字符串 ——
否则加载时要重新解析，而解析可能因 mathjs 版本变化而失败。

## 五、能力边界（明确不做的）

| 不做 | 理由 |
|---|---|
| 自设**量纲** | 量纲是物理常量，自设「长度」会破坏所有换算 |
| 自设单位参与**公式库** | 665 条公式的表达式假定 SI，混入自设单位会静默算错 |
| 自设单位**覆盖内置** | 那等于让 `1 m` 不再是 1 m，破坏「同输入同输出」 |
| 自设单位的**自动推导** | 「1 维尔 = 2 华里」需要解析，而华里也在表里 —— 可以做，但先做直接因子 |

## 六、接口设计

```
{ operation: 'unit_custom', action: 'add',    unit: {...} }
{ operation: 'unit_custom', action: 'list' }
{ operation: 'unit_custom', action: 'remove', name: '...' }
{ operation: 'unit_custom', action: 'check',  unit: {...} }   ← 只校验不落盘
```

`check` 是**干跑**：告诉用户「这个名字能注册吗、会不会撞已有单位」，
但不写盘。与老插件 `constants{preview}` 同一思路。

---

## 七、实现要点

1. **注册**：`math.createUnit(x_名, { definition: '1200 m' })`
2. **落盘**：写 `custom-units.json`
3. **加载**：引擎初始化时读盘并注册（**失败不致命**，跳过即可）
4. **显示**：`x_weiEr` → `@维尔`
5. **冲突检查**：
   - 名字已在标准表里 → 拒绝
   - 量纲 + 因子与已有单位相同（容差 1e-9）→ 警告但不拒绝
   - 名字含非字母数字 → 拒（mathjs 限制）
