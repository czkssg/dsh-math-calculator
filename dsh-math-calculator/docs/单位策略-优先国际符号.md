# 单位策略转向：优先国际符号（2026-11-17）

> 用户判断：「实在不行加提示词，尽量要求用英语专业词，中文别名太多了。」
> 这个判断是对的——中文别名是一张**永远补不完**的表。

## 一、为什么补别名治不了本

R53 一次性缺了 7 个：`石/节/牛顿/摩尔/吨标煤/摄氏/平方英尺`。
补完这 7 个，下一轮压测还会冒出别的（`钧`/`铢`/`营造尺`/`码磅`…）。

**结构原因**：中文单位是**开放集合**（每个朝代、每个行业都有一套），
而国际符号是**闭集合**（SI + 常用派生，就那些）。

继续补 = 用有限的人力追无限的表。

## 二、转向：提示词要求优先用符号

在 `TOOL_DESCRIPTION` 里加了一段（紧跟「物理量一律带单位写」之后）：

```
单位优先用国际符号（kg/kW/km/h/Pa/N/mol/degC/J/GJ/kcal/kn），不要用中文别名：
  中文别名是兜底表、覆盖不全（如「石」「吨标煤」常缺）；符号是标准，已全量注册。
  `1 节` 可能认不出，`1 kn` 一定行；`100 摄氏` 不如 `100 degC`。
  温度必须写 degC/degF（裸 C 是库仑）；光速是常量 c，不是单位。
```

## 三、但提示词不能是空话——先验证再承诺

我最初写的是「`1 kn` 一定行」，然后**去测**，发现 `kn` 根本不存在：

```
kn     ✗ Unit "kn" not found
knot   ✓            ← 我只注册了 knot，漏了缩写
kcal   ✗ 原生就没有
cal    ✗ 原生就没有
```

**如果照原样发出去，AI 照提示词用 `kn` 反而会撞 unknown_symbol——比不提示更糟。**

补齐 18 个常用符号（kn/nmi/kcal/cal/kJ/kWh/Wh/GJ/MJ/kN/kmol/kPa/MPa/mbar/mmHg/at…），
再扫 55 个跨量纲用例，只剩 `c → m/s` 失败——那是**常量不是单位**，
所以提示词里补了一句「光速是常量 c，不是单位」，而不是硬注册一个假单位。

## 四、加守护测试（关键）

`unit-symbols.mjs` **11 项**：

| 检查 | 作用 |
|---|---|
| 提示词点名的 12 个符号全通 | 承诺兑现 |
| 13 组常见符号（长度/质量/能量/电学/数据…）全通 | 防漏 |
| 提示词确实含「优先用国际符号」「degC」「常量」 | 防提示词被改回去 |
| 6 个中文别名仍可用 | 兜底不失效 |

**这条测试的意义**：以后谁再改提示词说「XX 一定行」，测试会先逼他去验证。

## 五、最终策略

| 层 | 定位 |
|---|---|
| **国际符号**（kg/kW/kn/degC…） | **主路径**：提示词要求优先用，守护测试保证全通 |
| 中文别名（米/公里/斤/石/节…） | **兜底**：常用词保留，生僻词不保证 |

这不是「放弃中文」，而是把它从「必须全覆盖」降级为「尽力而为」。

- 全库 **112 套 / 2,599 项全绿**；`doccheck` / `preflight` 通过。
