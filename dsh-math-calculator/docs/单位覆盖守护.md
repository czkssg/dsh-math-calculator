# 单位覆盖守护（2026-11-17）

> 用户要求：遍历 `units.json` 里所有带中文别名的单位，逐个验证能换算（防止再漏）。

## 一、扫出来的真相：不是漏 7 个，是漏 381 个

R53 报了 7 个中文单位缺失。我按用户要求做全量扫描：

| 阶段 | 可换算 | 覆盖率 |
|---|---|---|
| 初始 | **78 / 459** | **17%** |
| 修完 | **488 / 506** | **96.4%** |

**R53 抓到的 7 个只是冰山一角。** 根因是两份表从不同步：

| 表 | 条数 | 作用 |
|---|---|---|
| `units.json` | **459** 条带中文别名 | 知识库（全量） |
| `CJK_UNIT_ALIASES` | **172** 条 | 手写别名表（实际生效的） |

差出来的那批（`公尺`/`分米`/`公分`/`海里`/`浪`/`俄里`…）—— **数据在，但从没接上**。

## 二、修法：不再维护两份表

**① 自动生成别名映射**

```js
// 手写表 + units.json 自动补充（手写优先，它带更准的映射如 里 → cnli）
const sorted = [...CJK_UNIT_ALIASES, ...autoCjkAliases()]
```

**② 自动注册全部单位**

`fur`/`verst`/`cubit`/`longton`/`Mearth`… 这些目标单位 mathjs 不认，
中文别名换对了、目标单位又挂。现在从 `units.json` 批量 `createUnit`。

## 三、踩到三个坑（都写进 AGENTS.md 了）

### 坑 1：中文单位不能直接映射到 SI 基准

```
担：factor = 50（1 担 = 50 kg）
若映射成「担 → kg」→ 1 担 被算成 1 kg  → 差 50 倍！
```

**这是数值错误，比「不支持」危险得多**——数字看着正常。

修法：中文名注册成合成名 `cz<hash>`（带 factor），别名表把「担」指向它。

验证：

| 单位 | 映射 | 期望 | 结果 |
|---|---|---|---|
| 担 | kg | 50 | **50** ✓ |
| 钱 | kg | 0.005 | **0.005** ✓ |
| 步 | m | 1.6 | **1.6** ✓ |
| 舍 | m | 48000 | **48000** ✓ |

### 坑 2：过滤条件把中文名提前排除了

```js
if (!/[A-Za-z]/.test(name)) continue   // 中文名里没有 A-Za-z → 全被跳过
```

于是 `cz*` 注册了 **0 个**。改成 `/[A-Za-z\u4e00-\u9fa5]/`。

### 坑 3：Unicode 微符号归一位置错了

`µg`/`µs`/`m²` 是**别名替换的产物**（`微克` → `µg`），
放在替换**之前**做等于没做（那时还是三个汉字）。要放在替换**之后**。

## 四、守护测试（16 项）

`unit-coverage.mjs`：

| 检查 | 作用 |
|---|---|
| 全量 506 条，非例外项覆盖率 **≥ 96%** | 锁住覆盖率 |
| R53 点名的 6 个单位仍可用 | 回归保护 |
| 曾经缺失的 6 个（公尺/分米/公分/海里/浪/俄里）可用 | 修过的别退回 |
| 已登记例外有替代路径（degC / ohm） | 例外不是「没修」 |

### 已知例外（18 条，每条都写明原因）

| 类别 | 例 | 原因 |
|---|---|---|
| 温度 | 摄氏/华氏度/兰氏度 | 走 `degC`/`degF`/`degR`，`°C` 需特殊解析 |
| 希腊字母 | 欧姆/千欧/兆欧 | `Ω` 非 ASCII，`createUnit` 拒收；用 `ohm`/`kohm` |
| 变音符号 | 波兰沙任/葡丈 | `sążeń`/`braça` 注册不了 |
| 计数 | 人/人峰值 | 不是物理单位 |
| 歧义 | 市分/市厘 | 长度与质量两家都用，按长度解析 |

**关键**：例外表里每条都写原因，不写原因的等于把测试改绿。

## 五、顺手修正一条过时断言

`feedback-defects` 里有一条：「点」不该被当时间单位。

但 `units.json` 里**确实有**这个单位：

```json
{ "name": "点", "dimension": "time", "factor": 1440,
  "note": "古代报时单位，一昼夜 100 刻又分点，约 24 分钟/点" }
```

**数据是对的，断言过时了**——那条针对的是旧版把「排版点」误当时间的 bug。
改成校验「1 点 = 1440 s」。
