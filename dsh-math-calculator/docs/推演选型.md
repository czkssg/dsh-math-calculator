## 一、天文计算

### 候选

| 候选 | 版本 | 许可 | 周下载 | 最后更新 | 判断 |
|---|---|---|---|---|---|
| `astronomy-engine` | 2.1.19 | MIT | 455,106 | 2023-12 | ⚠️ 备选：API 简洁（升落/月相/季节），但停更 3 年 |
| `astronomia` | 4.3.0 | MIT | 1,425,035 | 2026-11 | ✅ 首选（若需要真实星历）：Meeus《天文算法》JS 移植，含 kepler/moonphase/rise-set/deltat |
| `suncalc` | 2.1.4 | 见包内 LICENSE（BSD-2） | 575,208 | 2026-11 | ⚠️ 备选：只做日升日落，覆盖太窄 |

### 它们有什么

- 给定**真实日期**，算太阳/月球/行星的视位置、升落时刻、月相、日食。
- 开普勒方程、地平坐标转换、黄赤交角。

### 它们没有什么（关键边界）

- **不能**接受"任意轴倾角 + 任意恒星 + 任意轨道半长轴"的架空星球参数——
  这些库内置的是地球轨道根数与地球自转。
- **不能**给出纬度气候（辐射平衡 + 环流 + 反照率反馈）。
- **不能**判断"这颗行星会不会被潮汐锁定"（需要潮汐演化模型，库只给当前位置）。

### 结论

`world` 的定位是**参数化架空星球**，不是"给定日期的真实星历"。
两者接口不匹配：强行接入只能取到"地球在某一天的数据"，与用户设定无关。

**第 6 步 runtime 不引入天文库。** 若要增强"地球参数还原地球"的实证校验，
可以在测试里把 `astronomia` 作为 devDependency 做对照（用真实月相/升落时刻
校验我们算的昼长与季节），但不进 `dependencies`。

## 二、气候模型

npm 搜索 `energy balance climate model` / `climate model javascript`：
返回的是 d3-sankey、MILP 求解器等无关包，**没有 JS 生态的辐射平衡/环流模型**。
Python 有 climlab / pyRTM，但本项目是纯 JS 插件。

**结论：自写分层模型。** 老实现的三层结构（辐照度 / 季节成因 / 纬度分布）
与标定系数是设计资产，重写保留数学关系与标定口径，不保留代码结构。

### 精度声明（写进输出）

- 第 1 层辐照度、至日高度角、昼长：几何关系，【精确】。
- 第 2 层季节成因分离：四次根折算 + 热惯性阻尼是标定过的，【标度】。
- 第 3 层纬度气候：系数由地球实测温度标定，【标度】至【量级】。

## 三、敏感性与参数扫描

npm 无 Sensitive Analysis / Sobol 实现（`salib` 是 Python）。
本项目只需要：

- 单点导数（sensitivity）：有限差分，自写；
- 整链重算（chain）：表达式链式求值，用 mathjs，不需要扫描库；
- 逐点表（sweep）：自写循环 + 转折点检测。

**结论：不引入依赖。**

### 7.2 重写后的位置

### 7.3 hierarchy 的自由拓扑

老接口（`levels/tree/base|total`）保留为等比链模式；新能力是 `nodes + parent/edges`：

```json
{"nodes":[
  {"id":"师","own":10,"level":1},
  {"id":"团1","parent":"师","count":3,"own":8,"authorized":3,"level":2},
  {"id":"独立营","parent":"师","level":3,"own":5,"props":{"type":"工兵"}}
]}
```

- `count`：该级实有单位数；`own`：本单位直属人数（不含下级）
- `authorized`：应有单位数 → 缺编/超编只**报告**，不报错
- `level` + 父节点 level → 跨级自动标记
- `props`：自由字段（兵种/驻地），输出按 `type` 统计分布
- 环 / 悬空父 / 重复 id / 多根未指定 → **报错**（算出来的数没有意义）

## 八、实体拓扑（第 7 步，2026-11-13 补）

### 8.1 开源调研

| 候选 | 版本 / 许可 | 判断 |
|---|---|---|
| `@turf/distance` | 7.4.0 / MIT，依赖 5 个 | ❌ 大圆距离**写死地球半径**；架空星球半径不同，需二次换算或自写。公式是公开知识，自写 8 行更直接 |

| `graphology-components` | 1.5.4 / MIT，停更 2022-06 | ✅ 引入：连通分量（无向图判圈要用：E − N + C） |
| `rbush` | 4.0.1 / MIT | ⏸ 空间索引；当前规模（几十节点）不需要 |
| 视线/视域 | — | ❌ 无成熟库（空间拓扑规划已记录），自写采样 + 曲率下沉 |

**结论**：新依赖 2 个（graphology-shortest-path、graphology-components），都零传递依赖之外的官方包，MIT。
距离与视线自写；两者的能力边界写在代码注释里。

### 8.2 模块

src/features/topology/geometry.ts   距离 / 最短路径 / 视线 / 可达预算

### 8.3 两个踩过的坑

1. **graphology-shortest-path 的导入形状**：CJS 包，`module.exports` 是对象
   （`{bidirectional, singleSource, brandes}`），ESM 下 `import { dijkstra }` 拿到的是
   命名空间 object，不可调用。用 `createRequire` 直接拿 CJS 原样。
2. **无向图的「环」**：`graphology-dag.hasCycle` 会把**每条单边**判成环（A→B→A）。
   无向图的判据是圈数 = 边数 − 节点数 + 连通分量数 > 0。
3. **dijkstra.singleSource 返回完整路径**，不是前驱表；当前驱表用会重建出错误的路径。
4. **视线的眼高单位**：elevationM 是米，眼高写 0.0017（把米当 km）会导致 1km 外的平地也被判遮挡。

## 九、面状绕障（2026-11-18）

需求：`topology route` 只有图上最短路，回答不了「山/湖/禁飞区挡在中间，怎么绕」。

| 方案 | 评估 |
|---|---|
| `@turf/shortest-path` 7.4.0（MIT） | 依赖 10 个 turf 子包；距离用 `@turf/distance`，**地球半径写死**——架空星球半径不可配 |
| `@turf/boolean-point-in-polygon` | 只有点包含判定，不含寻路 |
| 自写栅格 A*（约 200 行） | 零依赖、半径可配、可控安全间距与路径采样；栅格离散误差约 1 格 |

结论：**自写**。实现 `src/features/topology/avoid.ts`（MinHeap + 8 邻域 A*；
局部平面近似转 km，长度用 haversine 复核）。入口 `topology action:"avoid"`。
