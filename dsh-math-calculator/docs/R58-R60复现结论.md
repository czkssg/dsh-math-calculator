## 二、根因与修法

### 1. 公式参数「量纲/量名」标注错（最大头，33 条数据）

复现：`ideal_gas` 传 `R:"8.314 J/(mol*K)"` 报「期望 无量纲」；`beam_section_modulus.b` 标成「活度（T⁻¹）」；
`diffusion_coeff`、`case_depth.D0` 标成无量纲；`kiln_firing_time.heating_rate` 标成「速度」。

同类扫描（按 desc 里的单位）后一次修掉：**气体常数 15 条、导热系数 5 条、比热容 8 条、
截面宽 4 条、扩散系数 4 条、升温速率 1 条**。中文量名同步改对（用于关系图连边）。

### 2. 输出单位与 SI 计算不一致（8 条 expr）

引擎把带单位参数一律换成 SI 基准；`unit` 只是显示单位。所以 expr 必须自带到显示单位的换算：

| 公式 | 修前 | 修后 |
|---|---|---|
| `kiln_firing_time` | 1080 K ÷ 150 K/h = **25920** 标 h | `/3600` → **7.2 h** |
| `reactor_residence_time` | 秒 标 h | `/3600` → 2 h |
| `adsorption_breakthrough` | 秒 标 h | `/3600` |
| `oxygen_depletion` | 秒 标 min | `/60` → 10.5 min |
| `gear_geometry` | 米 标 mm | `*1000` → 40 mm |
| `admin_radius_from_info` | 米 标 km | `/1000` → 100 km |
| `hardness_yield_generic` | Pa 标 MPa | `/1e6` |
| `gear_contact_stress` | √Pa 标 √MPa | sqrt 内 `/1e6` → 219 MPa |

另修 `kiln_heat_balance.unit`：MJ → **kJ**（expr 里已 `/1000`），`ware_specific_heat` 描述改为 J/(kg·K)。

### 3. `consistency` 负数+单位抽 0 条（R58 #1，高）

- 正则的符号原先不在数字组里，`-876 kJ/mol` 整条不匹配；
- 现在支持 `-` / `−` / `－` / `负` / `+` 前缀，单位后缀不阻断；
- 判冲突改用**绝对值**算倍数（-876 vs -324 → 2.7 倍），正负号相反直接算冲突。

### 4. `sanity` 批量锚点未实现（R58 #2，高）

help 早已承诺「批量 expressions 里的 sanity」，但没有实现。补上：

```
{label:"大数", expr:"1e12", sanity:{max:1e10, note:"测试上限"}}
→ ⚠ 超出锚点上限 1e10（测试上限） 达 100 倍
→ value.items[0].sanityStatus = "violated"
```

- 键：max / min / expect（expect 是数量级，`expect:3` 即 10³）/ note；
- 判据由调用方给，工具只比对；不声明则零提示；量纲不可比（非数值）标 unknown。

### 5. `nautical mile` 缺（R58 #5，中）

`nmi` / `海里` 本来就有，但**含空格的英文全称**没进归一链：
引擎的英文别名规则只收单 token。扩成「两词全称」后，`10000 nautical mile = 18520 km`。

### 6. `units` 代入过程暴露内部代号 `raddose`（R58 #8，低）

`1 MJ/kg` 被 mathjs 显示为 `1e+8 raddose`（同量纲的吸收剂量单位）。
代入过程改为按量纲拼 SI 基准：`1e+6 m^2 / s^2`。

### 7. `backtrace` 推荐链不对口（R58 #6，中）

目标「这座窑一天烧多少煤」的 2 字滑窗是「座窑/天烧/少煤」，而公式 keys 写的是「窑炉/耗煤/烧成」——
两头对不上，推荐链被「能养活多少人·日」（命中「多少」）抢走。

修法：领域单字（只从公式 keys/name 的汉字里收）+ 停用词（这座/一天/多少…）+ keys 加权 +
单字只在 keys 里计分。现在第一命中是 **窑炉热平衡**。

### 8. 公式缺失/别名（144 表 G 类，4 条）

- `rocket_equation`：库里确实没有 → **新增 1 条**（齐奥尔科夫斯基方程，带 sources）；
- `thermal_radiation` → `stefan_boltzmann`、`potential_gravity` → `potential_energy`：
  给已有公式补 keys 别名，并让 `formula` 的查找支持 keys **整词**命中（dispatch 与 callFormula 共用 `findFormula`）。

### 9. 顺手修的真错

`potential_energy.g`：desc 写 `m/s^2`，量纲却标成速度（T⁻¹）→ 改加速度（L T⁻²）。

   库里可能仍有同类错标（例如 `mix_temperature.c1/c2` 的 desc 只有「比热1」没有单位，无法自动推导）。
   下一步建议：逐条审计 1,946 个参数的 desc 单位，产出差异清单。
2. **expr 换算约定靠人记**：新公式必须「SI 输入 + 自带换算到 display unit」。
   建议加静态测试：对已知非 SI 输出单位（h/min/mm/km/MPa/kJ…）强制检查 expr 里含对应换算常数。
3. 144 表的 D/E/F/I 类没有重复修——它们已在 R51/R52 修过，本轮的复现记录在第二节开头。
