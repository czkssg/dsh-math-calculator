## 二、找到的两个中文项目

### 1. `program-in-chinese/chinese-unit-converter`（Java）

- 结构非常对味：`度量类型.java` / `度量衡制度.java` / `单位.java` / `功能.java`
- **但数据量太小**：只有约 40 个单位（`单位.java` 是 54 行枚举）
- 有价值的只有分类法：公制/市制/英制 × 长度/质量/面积/体积

**判断：分类法可借鉴，数据量不足以扩充我们的 465 条。**

### 2. `east0923/east-measure`（JS）

- `dist/dict.json` 是**结构化中文词典**：

```json
{ "length": { "show": {"zh": "长度"},
  "units": { "m": { "show": {"zh": "米"}, "sign": "m", "a": 1, "b": 0 } } } }
```

- 覆盖 **27 个量纲 / 66 个单位**，偏工业传感器场景（含浊度 NTU、PH、电导率）
- 换算模型是线性 `y = a·x + b`（能表达温度与浊度）

**判断：数据量仍小于我们，但有 10 条独特中文写法可收。**

## 三、最终合入：10 条（逐条判定，不照单全收）

| 中文 | 目标 | 判定 |
|---|---|---|
| 时 | h | ✅ 收（小时简称） |
| 千米每小时 | km/h | ✅ 收 |
| **摄氏度** | **degC** | ⚠️ **改目标**（原给 `C`，那是库仑） |
| **华氏度** | **degF** | ⚠️ **改目标**（原给 `F`，那是法拉） |
| 牛 | N | ✅ 收 |
| 角度 | deg | ✅ 收 |
| 转 | turn | ✅ 收 |
| 百分数 | pc | ✅ 收 |
| 千赫兹 | kHz | ✅ 收 |
| 兆赫兹 | MHz | ✅ 收 |
| **分钟** | ~~m~~ | ❌ **丢弃**：`m` 在我们这里是「米」，加「分钟」会歧义 |

**这就是「不要照单全收」的具体含义**：east-measure 用 `C` 表示摄氏、`m` 表示分钟——
在它的语境里没问题（它没有库仑、没有米），但在我们的体系里是**直接冲突**。

## 四、顺带发现并修好一个结构问题

收「摄氏度」时发现：中文名挂在 `°C` 这个单位上**解析不了**——
因为 mathjs 不认 `°C`，要靠 `SYMBOL_UNITS` 折成 `degC`。

**修法**：新建 `degC` / `degF` / `degR` 三个 ASCII 单位承载中文别名，
符号单位（`°C`/`°F`/`°R`/`°Ré`）只留符号。

验证：

```
32 华氏度 → degC      0 degC        ✓
100 摄氏度 → degF     212 degF      ✓
0 摄氏度 → K          273.15 K      ✓
491.67 兰氏度 → K     273.15 K      ✓
```

## 五、诚实结论：没有权威中文开源词典

| 期望 | 实际 |
|---|---|
| 下载权威中文度量衡词典 | ❌ **不存在**（UCUM 无中文，GNU/pint 是英文，两个中文项目各 <70 条） |
| 扩充中文别名 | ✅ 现有 611 条（人工整理）+ 本轮 +8 条 |

**中文单位别名只能靠人工按度量衡体系整理**，这是客观情况，不是没尽力：

- 中文维基不可达
- 国内开源项目规模都在几十条量级
- 权威资料（《中国科学技术史·度量衡卷》《法定计量单位手册》）是纸质书
