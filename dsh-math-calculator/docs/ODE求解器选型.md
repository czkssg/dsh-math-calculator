## 二、实测证据

```
方程   dy/dt = -0.5·y,  y(0)=100,  区间 [0,10]
解析解 y(10) = 100·e^-5 = 0.67379470

ode-rk4（dt=0.01, 1000 步）  →  0.6737946999261668    误差 7e-11  ✓
```

对比我手写版本：**第一步就崩**（BigNumber 拒绝 >15 位 number），
修正后虽能算，但要自己处理：
- RK4 四阶的中间态隔离
- 15 位有效数字截断
- 发散检测
- 刚性判据

**`ode-rk4` 一行就解决前两项。**

## 三、为什么仍保留部分自写

| 能力 | 谁做 | 为什么 |
|---|---|---|
| RK4 主循环 | **`ode-rk4`** | 库的强项，且零依赖 |
| 15 位截断 | 自己（包在 `deriv` 回调里） | 库不知道 BigNumber 的限制 |
| 发散检测 | 自己（`Number.isFinite` 判 `y`） | 库不检查 |
| 刚性提示 | 自己 | **库不做这个判断** |
| 表达式求值 | 自己（`engine.evaluate`） | 库只接受 JS 函数 |

**刚性提示为什么必须自写**：

```
dy/dt = -1000·y   在 dt=0.01 时，RK4 稳定域被突破
→ 数值爆炸，但❌库不会告诉你「这是刚性问题，调小步长」
→ 只会给出发散的结果
```

而「这一步内状态变化超过自身量级」这个判据是**领域知识**，
不是数值方法能自动提供的。
