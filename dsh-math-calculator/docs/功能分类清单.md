# ① 数值计算（16 个 operation，2,794 行核心代码）

## 1.1 能力清单

| operation | 作用 | 状态 |
|---|---|---|
| `evaluate` | 表达式求值（含批量/单位/量级标注） | ✅ |
| `solve` | 解方程/方程组 | ⚠️ 无解与无穷多解不分（A5） |
| `system` | 线性方程组 | ✅ |
| `derivative` | 符号求导 | ✅ |
| `integral` | 符号积分（含定积分） | ✅ |
| `simplify` / `expand` | 化简 / 展开 | ✅ |
| `roots` | 求根 | ✅ |
| `matrix` | 矩阵画像（秩/零空间/奇异值/逆） | ✅ |
| `eigen` | 特征值 | ✅ |
| `stats` | 统计量 | ⚠️ `dataY` 长度不校验（T7-N3） |
| `dist` | 概率分布 | ✅ **已修 t 分布 bug** |
| `regression` | 回归拟合 | ⚠️ `degree<=0` 静默当 1（T7-N6） |
| `ode` | 微分方程 | ✅ 有刚性检测 |

| `units` | 单位换算 | ⚠️ **上标 `kg/m³` 不认** |

## 1.2 代码分布

| 文件 | 行数 | 职责 | 换开源？ |
|---|---|---|---|
| `stats.ts` | 452 | 分布/回归/描述统计 | ✅ **已换 jstat** |
| `numeric.ts` | 339 | SVD/秩/零空间 | ✅ **已换 ml-matrix** |
| `symbolic.ts` | 279 | 符号微积分 | ✅ **已用 algebrite** |
| `ode.ts` | 462 | RK4 + 刚性检测 | ❌ 无可用开源（保留） |
| `systems.ts` | 320 | 方程组解析 | ⏸ 可试 ml-matrix |
| `format.ts` | 942 | 数值格式化 | ❌ 自己写更合适 |

## 1.3 缺什么

**这一类的核心缺口是「复合单位」**：

```
kg/m^3  → g/cm^3   ✅
kg/m3   → g/cm3    ✅
kg/m³   → g/cm³    ❌ 不认识     ← 中文设定最常用的写法
```

不是缺一个单位，是**整个复合单位的实现方式是补丁式的**。
已立项：[复合单位体系规划](复合单位体系规划.md)（量纲代数 + UCUM 库，4.5 天）。

## 2.2 代码分布

| 文件 | 行数 | 性质 |
|---|---|---|
| `formulas.ts` | 830 | 检索打分逻辑 |
| `formula-systems.ts` | 879 | **22 条推演链（333 个数据项）** |
| `formula-table.ts` | 277 | 参数表 |
| `formula-pack.ts` | 189 | 打包 |
| **+ 27 个 `formula-library-*.ts`** | **13,049** | **665 条公式定义（纯数据）** |

## 2.3 能不能换开源

**数据部分不能换** —— 665 条公式是本项目最有价值的资产，没有开源库能替代
（它们是「为架空世界推演挑选过的公式」，不是任意公式集合）。

**调动逻辑可以优化**：
- 检索打分 → 可考虑 `dsh-memory` 的 RRF 融合思路（但它需要向量路，本插件没有）
- 已借鉴：`dsh-memory` 的停用词机制（修虚词污染）

## 2.4 缺什么

| 缺口 | 影响 |
|---|---|
| **覆盖率只有 31.7%** | 665 条里 454 条不在任何体系链中，「查得到但连不起来」 |
| `chains` 不可计算 | 22 条链只能**查**，不能算「A 变 X% → 末端变多少」 |
| 无「按场景找公式」 | 只能按名字/描述搜，不能按「我要推兵役制度」找相关公式集 |

# ④ 依赖因果图谱（5 个 operation，1,897 行）

> ⚠️ **这一类的名字容易混**。用户说的「依赖因果图谱」是**抽象的依赖/因果传导**，
> 与「实体拓扑模型」（第五类，空间的）是两件事。

## 4.1 能力清单

| operation | 作用 | 状态 |
|---|---|---|
| `dependency` | 有向图传导：上下游/环/层深/跨度 | ✅ 本轮新建 |
| `consistency` | 同一量多处不同值（如 920 亿 vs 8 亿 → 差 115 倍） | ✅ |
| `ledger` | 分项之和 vs 总量闭合 | ✅ |
| `compare` | 方案对比（不给权重就不给综合分） | ✅ |
| `interval` | 区间运算（上下界进、上下界出） | ✅ |

## 4.2 代码分布

| 文件 | 行数 | 换开源？ |
|---|---|---|
| `interval-op.ts` | 495 | ❌ 自写更贴需求（四点验证乘法） |
| `consistency-op.ts` | 423 | ❌ 领域语义 |
| `dependency-op.ts` | 416 | ⏸ **可换 `graphology`**（见下） |
| `ledger-op.ts` | 290 | ❌ 领域语义 |
| `compare-op.ts` | 273 | ❌ 领域语义 |

## 4.3 ★ 这一类的真实缺口：`dependency` 是手写的

`dependency-op.ts`（416 行）里手写了三个算法函数，**合计 98 行**：

```
buildAdjacency   建邻接表
traverse         BFS 传导（含上下游方向）
findCycles       DFS 环检测
```

**而 `graphology` 早就有这三样**：

```
graphology/components      连通分量
graphology/dag             环检测 + 拓扑排序
graphology/shortest-path   Dijkstra / A*
graphology/traversal       BFS / DFS
graphology/metrics         density / centrality
```

**这正是用户立规矩的直接起因**（「手搓代码换开源」）。
按同一条路子（ml-matrix、jstat）应该**换成 graphology**。

## 4.4 缺什么

| 缺口 | 说明 |
|---|---|
| `dependency` 未换 graphology | 手写三函数共 98 行可删 |
| **因果 ≠ 依赖** | 现在只有「A 依赖 B」（结构），没有「A 导致 B」（强度/时滞） |
| 无跨体系的因果链 | 665 条公式之间的依赖只有 45 个接点，深度传导算不了 |

# ⑤ 实体拓扑模型（**0 个 operation**，完全缺失）

## 5.1 这是什么

用户明确：**实体的空间拓扑** —— 地质地形、建筑、载具等实体的**几何与连通结构**。

几何层（距离/行军/遮蔽）只是它的**自然延伸**，不是独立功能。

## 5.2 现在有什么

| 现有 | 提供什么 | 有空间吗 |
|---|---|---|
| `world` 的 `terrain` | 单点局地气候（日照/气温） | ❌ 无位置 |
| `bodies` | 天体数据 | ❌ 无位置 |
| `dependency` | 抽象传导 | ❌ 无位置 |

**全都没有空间概念。**

## 5.3 差什么（这一类是最大缺口）

```
① 距离      两点间最短路径（按地形加权，非直线）
② 行军      距离 ÷ 地形速度系数 → 天数
③ 遮蔽      视线是否被高地阻挡
④ 视域      某点能看到哪些区域
⑤ 连通      某节点被毁，哪些区域失联
⑥ 通行      这条路径对某类载具是否可走
⑦ 建筑/载具  楼层、舱室、门窗、管道的可达性
```

## 5.4 开源选型（已调研，未实施）

| 层 | 候选 | 结论 |
|---|---|---|
| 图算法 | `graphology` | ✅ MIT、221 万周下载（⚠️ 2 年未更新） |
| 地理几何 | `@turf/turf` | ✅ MIT、231 万周下载，含 **`shortestPath`**（绕障寻路） |
| 视线/视域 | **无成熟库** | ❌ 须自写约 150 行 |
| 地形语义 | **无库可依** | ❌ 领域知识（山地×2.5 等） |

详见 [空间拓扑层规划](空间拓扑层规划.md)。

# 由此得出的重构优先级

按「用户要的五类」重排，而不是按阶段编号：

| 优先 | 动作 | 目标类别 | 成本 | 为什么这个顺序 |
|---|---|---|---|---|
| **1** | **`dependency` 换 `graphology`** | ④ | 0.5 天 | **最符合「手搓换开源」的本意**：手写三函数 98 行可删 |
| **2** | **`units.ts` 复合单位重做** | ① | 4.5 天 | 唯一「用户不设参数也出错」的一类 |
| **3** | **`entity_topology` 实现** | ⑤ | 4 天 | **最大能力缺口**，且 graphology/Turf 已就位 |
| 4 | `chain` 链条传导 | ③ | 2 天 | 推演核心形状缺失 |
| 5 | 修反馈包 46 条缺陷 | 全部 | 3 天 | 报告已冻结，排在这些之后 |

**第 1 项最该先做**：它只要半天，且是「手搓换开源」这条规矩最直接的兑现
（`graphology` 就在那里，我们还在手写 BFS）。

**第 3 项是最大缺口**：五类里唯一 0 operation 的一类。
