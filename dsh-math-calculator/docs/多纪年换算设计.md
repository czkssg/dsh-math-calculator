# 多纪年换算设计（2026-11-27）

> 目标：回答「A 历法的某某年，等于 B 历法哪一年」「某年号第几年是哪一年」。
> 上游：[固化边界与缺口清单](固化边界与缺口清单.md) #4「时间线一致性（多纪年混用）」。
> 复核：`timeline_check` 只查事件跨度/重叠；`calendar-convert` 只做**单历法**的“年内第几天 ↔ 绝对天数”。

## 一、缺口定位

| 能力 | 现状 |
|---|---|
| 同一历法内：某年第几天 ↔ 绝对天数 | ✅ `astro action:"calendar-convert"` |
| 事件时间线是否跨度异常/重叠 | ✅ `timeline_check` |
| **A 历法年份 → B 历法年份**（跨历法/跨纪元） | ❌ 0 条 |
| **年号第 N 年 → 绝对年** | ❌ 0 条 |

## 二、开源记录（硬门槛 ①②）

| 渠道 | 结果 | 评估 |
|---|---|---|
| 已有依赖 | `astronomy-engine`（^2.1.19）提供儒略日（JD）与真实公历互转 | 真实公历已由 `astro` 覆盖；**架空历法**它不认识 |
| npm | 无「多纪年/架空历法映射」库 | 不引 |
| 领域标准 | 儒略日编号（JDN）是跨历法换算的通用枢纽；**线性历法**之间的换算是一次仿射变换 | 按仿射变换实现 |

**关键判断**：架空世界的历法通常是**线性**的（每年固定天数 + 一个纪元起点），
跨历法换算就是 `(源年 − 源纪元) × 年长比 + 目标纪元`。**带闰年/不规则插值的历法不做**——
那需要完整规则表，本项目没有，硬做只会算错。

## 三、两条公式

### 3.1 `era_year_convert`（A 历法年份 → B 历法年份）

```
目标年 = (源年 − 源纪元) × (目标年长 / 源年长) + 目标纪元
```

- 两历法年长相同 → 退化为平移（最常见）；
- 年长不同（如 360 天 vs 365.25 天）→ 按比例；
- 例：源历 360 天/年、纪元 0，目标历 365.25 天/年、纪元 1000；源年 100 →
  `100 × 365.25/360 + 1000 = 1101.46`。

### 3.2 `regnal_year_to_absolute`（年号第 N 年 → 绝对年）

```
绝对年 = 年号起始年 + 第几年 − 1
```

- 「某年号第三年」= 起始年 + 2（**不是 +3**，这是最常见的差一错误）；
- 例：年号起于 1644，第 3 年 → **1646**。

## 四、验证方式

1. **平移退化**：年长比为 1 时，结果 = 源年 + (目标纪元 − 源纪元)；
2. **比例正确**：年长比 365.25/360 时按比例放大；
3. **往返一致**：A→B→A 应回到原值（容差 1e-9）；
4. **差一检查**：年号第 1 年 = 起始年；第 N 年 = 起始 + N − 1；
5. **边界**：源年长为 0 不能静默给 Infinity。

测试：`test-v3/r108-era-convert.mjs`。

## 五、明确不做

- **闰年/不规则历法**：需要规则表，做不了就明说；
- **月/日级别的跨历法换算**：需要两个历法的月长规则，同理不做；
- **儒略日往返**：真实公历交给 `astro`（已有 astronomy-engine）。
