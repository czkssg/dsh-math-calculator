## 二、开源检索（铁律，先查再写）

**结论：这五个方向都没有「拿来即用」的轻量库，但都不需要新重依赖**——
贸易用 graphology + 公式，生态用 Lotka-Volterra + 物种-面积律，疾病用 SIR 方程。

## 三、优先级（按「闭环贡献 ÷ 成本」）

### P1-① 贸易网络（`trade`）

```
输入：各地产能/需求、运费单价、关税
模型：比较优势 → 引力模型（流量 ∝ 产出A·需求B / 距离^β）
输出：流向矩阵、总运费、贸易依存度、断供风险（去掉一条路线谁先崩）
```

为什么先做：**它是「有产能」与「有历史」之间唯一缺的一环**。

### P1-② 生态/食物网（`ecology`）

```
输入：面积、纬度、连通度
模型：物种-面积律 S = c·A^z（z≈0.25）+ Lotka-Volterra 捕食链
输出：物种数估计、关键种、食物网稳定性（有没有「移除一个就崩」的节点）
```

为什么第二：承载力算的是「人」，生态算的是「这个世界有什么」。

### P2 疾病（`epidemic`）

SIR + 人口密度/贸易路线 → 爆发峰值、持续时间、死亡数。接在 `trade` 之后（沿贸易路线传播）。

### P2 星图（`sky`）

不引 d3-celestial；用已装 astronomy-engine 加「行星可见性 + 星座近似方位」——
输入日期/经纬 → 行星高度/方位、当空星座。

### P3 技术树（`tech-tree`）

从「资源 → 工艺 → 产品」的依赖链，公式库已有材料/机械条目，缺**前置依赖图**。

## 四、维护项（顺手做）

| 项 | 理由 |

## 五、验收标准（每项都要满足）

1. 地球/现实数据可校核（有残差或对照）；
2. 缺参报 `missing_params`，不瞎编；
3. 确定性（同输入同输出）；
4. 至少 8 项测试，含「该拒绝的拒绝 + 该放行的放行」；
5. skill/help/CHANGELOG 同步。
