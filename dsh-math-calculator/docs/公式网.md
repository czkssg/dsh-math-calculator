# 公式网（常数 → 公式 → 公式）

> 2026-11-18 · v3.12.0。全量依赖网：从**物理常数**出发，第一层是直接用到它的公式，
> 之后按「上一个公式的输出量 = 下一个公式的参数」继续向下，形成有向网。
> 守护测试：`test-v3/r64-formula-web.mjs`（15 项）；全量 123 套 / 3,021 项全绿。

## 二、构建口径（不含猜测）

### 常数边

公式**参数的默认值**等于该常数的标准值（相对误差 < 1e-6），即「这个公式天生就用这个常数」：

```
  E = mc²        → c（参数 c 默认 299792458）
  万有引力        → G（参数 G 默认 6.6743e-11）
  理想气体        → R（参数 R 默认 8.314…）
  黑体辐射        → sigma（参数 sigma 默认 5.670374419e-8）
```

这条口径比「表达式里出现常数」宽得多：多数公式把常数写在参数默认值里，表达式只有参数名。

### 公式边

上游公式的**输出物理量**（从 unit 括号或公式名匹配受控词表）与下游参数的 `quantity` 完全相同，
**并且**两端量纲一致时才连边。受控词表来自全部参数的 `quantity`（544 个词）。

不连的：量纲相同但语义不同（速度 ≠ 加速度）、只有弱相关（用 `formulas query:"neighbors"`）。

## 三、怎么查

```jsonc
{ "operation": "formulas", "query": "web" }                          // 全量统计
{ "operation": "formulas", "query": "web", "formulaFocus": "G" }      // 从 G 向下（默认 2 层）
{ "operation": "formulas", "query": "web", "formulaFocus": "orbital_velocity", "webDirection": "both" }
{ "operation": "formulas", "query": "web", "formulaFocus": "c", "webDepth": 3, "webLimit": 10 }
```

输出按层列公式（第 0 层常数、第 1 层直接使用、第 2 层起为下游），每层显示 `webLimit` 条（默认 20），
超出会写「另有 N 条」。

## 四、已知局限

- **输出量 identity 只覆盖 339 / 805 条公式**：其余公式的 unit 是「性能指数」「成本」这类自由文本，
  没有可对齐的物理量；这些公式只能作为网的叶子（有入边、无出边）。
- **参数 `quantity` 标注错会造假边**：本轮修了 48 条（g/a 是加速度却被标成速度、omega 是角速度、
  弹簧 k、应力、比潜热、摩尔质量、换热系数；`cobb_douglas.A` 是全要素生产率却被标成功率）。
- **高频量会分支爆炸**：速度、长度、时间接几十个公式；第 2 层可能上百条，用 `webLimit` 控制显示。
- 跨域同名量（功率 vs 压力、温度 vs 周期）靠 `quantity` 区分，标注不准时需要人工看。

## 五、与 neighbors 的区别

| 查询 | 性质 |
|---|---|
| `formulas query:"neighbors"` | 无向弱相关（共用参数/常数/标签，约 4 万条边），用来「找相关公式」 |
| `formulas query:"web"` | 有向强边（输出量 → 输入量 + 量纲），用来「沿依赖推下去」 |
