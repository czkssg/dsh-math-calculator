# 公式网（常数 → 公式 → 公式）

> 2026-11-19 · v3.15.0（工程/地质/社会扩展后）。全量依赖网：从**物理常数**出发，第一层是直接用到它的公式，
> 之后按「输出物理量组 = 下游参数组」继续向下；互引会形成环（闭合）。
> 守护测试：`test-v3/r64-formula-web.mjs`（21 项）；全量 123 套 / 3,027 项全绿。

### 闭合样例（互引产生的真实环）

```
  acceleration → kinematics_v → acceleration
  velocity_uniform → acceleration → kinematics_v → kinematics_s → velocity_uniform
  acceleration → kinematics_v → kinematics_s → kinematics_v2 → acceleration
```

测速公式的输出是速度，速度又是加速度公式的输入；加速度再喂回测速公式——这类环是物理量之间的真实互引，不是数据错误。

## 二、构建口径（不含猜测）

### 常数边

公式**参数的默认值**等于该常数的标准值（相对误差 < 1e-6），即「这个公式天生就用这个常数」：

```
  E = mc²        → c（参数 c 默认 299792458）
  万有引力        → G（参数 G 默认 6.6743e-11）
  理想气体        → R（参数 R 默认 8.314…）
  黑体辐射        → sigma（参数 sigma 默认 5.670374419e-8）
```

这条口径比「表达式里出现常数」宽得多：多数公式把常数写在参数默认值里，表达式只有参数名。

### 公式边（闭合版）

1. 从公式的 unit 维度 + 名称/描述消歧，得到它的**输出物理量组**（27 组：力/能量/力矩/功率/速度/加速度/时间/长度/面积/体积/质量/密度/温度/压强/频率/波长/电荷/电流/电压/电阻/电容/电感/模量/转动惯量/流量/物质的量/浓度/热容/导热系数/数量/比率/金额/指数）；
2. 下游参数的 `quantity`/desc 归到同一些组（**同义词组**：力 = 力/载荷/重量/张力/剪力；长度 = 长度/距离/位移/半径/高度…）；
3. 只有当**组相同且量纲一致**时才连边。

这样「力」的输出能接到「载荷」的输入，而不是因为参数词表只写「载荷」就断掉。
力矩与能量同量纲（M·L²/T²），靠名称里的「力矩/弯矩」区分；应力与压强同量纲，归同一组。

## 三、怎么查

```jsonc
{ "operation": "formulas", "query": "web" }                          // 全量统计
{ "operation": "formulas", "query": "web", "formulaFocus": "G" }      // 从 G 向下（默认 2 层）
{ "operation": "formulas", "query": "web", "formulaFocus": "orbital_velocity", "webDirection": "both" }
{ "operation": "formulas", "query": "web", "formulaFocus": "c", "webDepth": 3, "webLimit": 10 }
```

输出按层列公式（第 0 层常数、第 1 层直接使用、第 2 层起为下游），每层显示 `webLimit` 条（默认 20），
超出会写「另有 N 条」。

**每条都标清「输出量 → 参数」**：

```
  第 1 层 · 直接使用 G 的公式（16）：
    gravitation  万有引力（G → gravitation.G）

  下游 第 1 层（38）：
    power  功率（kinetic_energy 输出「能量」→ power.W）
  上游 第 1 层（56）：
    velocity_uniform  匀速速度（velocity_uniform 输出「速度」→ kinetic_energy.v）
```

## 四、已知局限

- **组匹配是近似**：力组把「载荷/重量/张力」都算力，长度组把「高度/深度/半径」都算长度；
  语义更细的区分（压力 vs 应力、力矩 vs 能量）靠组内关键词与量纲，仍有少量误连。
- **117 条无入边、34 条无出边**：前者是没有上游能喂它（纯外部输入公式），后者是没有下游接它（纯判定/量级公式）；
  这些是网的自然边界，不是缺陷。
- **高频组会分支爆炸**：速度/长度/时间组接几十上百个公式，第 2 层可能上千；用 `webLimit` 控制显示。
- 先前的精确版（8,995 条边、identity 339 条）已被闭合版取代；精确边仍在 `formulas query:"neighbors"` 的弱相关里可见。

## 五、与 neighbors 的区别

| 查询 | 性质 |
|---|---|
| `formulas query:"neighbors"` | 无向弱相关（共用参数/常数/标签，约 4 万条边），用来「找相关公式」 |
| `formulas query:"web"` | 有向强边（输出量 → 输入量 + 量纲），用来「沿依赖推下去」 |

## 六、与原有功能的耦合（AI 怎么调）

### 1. 公式调用自动带上下游

```jsonc
{ "operation": "formula", "formula": "kinetic_energy", "params": { "m": 2, "v": 3 } }
```

返回里多了 `value.web`：

```
{ "focus": "kinetic_energy", "canonical": "kinetic_energy",
  "upstream":   [{kind:"constant",id:"c"…}, {kind:"formula",id:"velocity_uniform",param:"v"…}],
  "downstream": [{kind:"formula",id:"relativistic_kinetic_energy",param:"v"…}] }
```

`notice` 里另有一行摘要，格式是 **「输出量 → 参数」**：

```
  网：上游 56：velocity_uniform（输出「速度」） → .v；…
      下游 46：输出「能量」 → power.W；…
  常数上游：c（输出 m/s，值 299792458） → .c
```

每条边都带 `output` 字段（公式为输出物理量组；常数为单位）与 `value`（常数数值）。
不想要就传 `webContext:false`。

### 2. 别名折叠（真重复已解决）

- 26 组同表达式公式（28 条）折叠为别名：`projectile_energy → kinetic_energy`、`ram_momentum → momentum` …；
- 网里只留主节点（节点数 859 → **831**）；`formulas query:"web" formulaFocus:"projectile_energy"`
  会自动指向主节点并在标题注明「是 kinetic_energy 的别名」；
- **调用别名仍可算**（公式表保留全部条目，兼容旧调用）。

### 3. 与 neighbors / chain 的关系

| 能力 | 性质 | 用途 |
|---|---|---|
| `formulas query:"neighbors"` | 无向弱相关（共用参数/常数/标签，约 4 万边） | 「还有哪些相关公式」 |
| `formulas query:"web"` + `value.web` | **有向强依赖**（输出组 → 输入组 + 量纲） | 「这个数往哪儿走 / 从哪儿来」 |
| `formulas query:"chain"`（sys-*） | 网中的一条**指定路径**（人工声明 dataFlow） | 「按步骤全链算一遍」 |

### 4. AI 的调用顺序（推荐）

```
① formulas query:"web", formulaFocus:"<目标>"  → 看它需要什么、能喂给谁（或直接调 formula 看 value.web）
② formula  → 拿到 value / parts / 适用域
③ 缺参时按 missing 列表补 initial，或按 web.upstream 先算上游
④ 想做全链：formulas query:"chain" + formulaFocus:"sys-…"，用 initial 补齐外部输入
```

### 5. 公式即函数（原有能力，未变）

`compileFormula` 的契约仍在：参数带单位会校验量纲、`overrides` 可覆盖任意参数、
返回值含 `value`、`parts`（分项）、`neighbors`（弱相关），现在再加 `web`（强依赖）。
