# R53 全量压测解读（2026-11-17）

> R53 列了 12 条问题，通过率约 70%。逐条复现后：**5 条已在旧构建里修好**，**4 条是真缺陷**（已修），**3 条是设计选择或文档**。

## 一、先说最要命的：`pressure` 的单位三处打架

R53 报「pressure < 1 atm 全崩（0.001–0.2）」。复现后发现**不是崩塌，是单位口径写错了三个地方**：

| 位置 | 写的是 |
|---|---|
| `world.ts` 内部 | `num(params.pressure, 101325)` → **Pa** |
| `world-op.ts` 校验标签 | `pressure（Pa）`，min=1 |
| `tool.ts` schema 描述 | **`world：地表气压 atm`** ← 唯一写错的 |

三处里只有 schema 写错成 atm。于是按 schema 填 `pressure: 0.1`（0.1 atm）会被当成 0.1 Pa 拒掉。

**修法**：schema 改成「Pa（地球 101325；火星 610；不要写 atm）」，并在越界 hint 里给换算。代码逻辑不动（现有测试全按 Pa 传参，是对的）。

## 二、中文单位 7/10 缺失 —— 根因有两层

### 第一层：别名表没有这些词

`CJK_UNIT_ALIASES` 有 `摄氏度` 却没有 `摄氏`，有 `米/公里/斤` 却没有 `节/牛顿/摩尔/平方英尺/石/吨标煤`。
能用的那几个是「恰好有」，不是设计。

### 第二层（更隐蔽）：一个 try 吞掉四条注册

```js
try {
  math.createUnit('AU', …)
  math.createUnit('barrel', …)
  math.createUnit('bbl', …)
  math.createUnit('tce', …)      // ← 前面的抛了，这条就永远不执行
} catch { /* 静默 */ }
```

实测：`tce` **单独注册成功**，一起注册就消失。改成逐个 try 后正常。

## 四、修这些时踩出来的一个回归（值得记）

加完 `石` 之后，`units-custom` 套件崩了：

```
1 石炭 to MJ   →   1 cndan炭 to MJ   →   语法错
```

「石炭」是煤（完整词），被「石」拆成两半。根因是别名匹配**只判前文、不判后文**：

```js
// 前文：1 石  ← 「石」前面是数字 → 放行
// 后文：「炭」紧跟其后 → 应该挡住
```

补上后边界判断（别名后紧跟汉字 → 说明只是更长词的一部分 → 不替换）。
