# dsh-math-calculator 功能详解

> 面向**使用者**的功能说明。装什么、怎么算、每个 operation 能做什么、
> 结果该怎么读、什么时候它会拒绝你。
>
> 版本：2.2.0 ｜ 30 个 operation ｜ 404 条公式 ｜ 88 个单位 ｜ 26 个具名天体 ｜ 32 类天体类型
> 测试：83 套 / 3918 项

## 一、它是什么，不是什么

| | |
|---|---|
| **是** | 本地数学与物理**推演引擎**：计算 + 约束检查 + 可信度标注 |
| **不是** | 计算器。计算器只给数，它还给"这个数能信到什么程度、在什么条件下失效" |

这个区别是全部设计的起点。举一个真实例子：

```
问：1.5 倍重力下，花岗岩山能长多高？
计算器：4893 m
本插件：3262 m，并提示「已接近花岗岩极限，再高会塌」
```

第二个数不是"更准的 4893"。它是**先把材料强度算进去**得到的上限——
4893 在 1.5 倍重力下会让山脚岩石直接压碎，也就是那个数物理上不存在。

所以本插件的输出里始终带着三样东西，**它们不是装饰，砍掉就等于砍掉一半功能**：

- **可信度标签**：`[精确]` / `[标度]` / `[量级]` / `[仅方向]`
- **适用域警告**：这个公式在什么条件下失效（哪些是"仅地球成立"）
- **跨模块一致性检查**：几处设定之间是否自相矛盾

## 二、三层精度：最容易搞错的地方

插件有三个精度概念，**它们的用途完全不同**：

| 参数 | 语义 | 默认 | 什么时候动它 |
|---|---|---|---|
| `precision` | **计算**精度（BigNumber 有效位） | 64 | **永远不要动** |
| `displayPrecision` | **显示**精度：**小数点后几位** | 8 | 想少看几位小数时 |
| 工作区固化 | 同上，但持久保存 | — | 一段对话里定一次 |

### 为什么 precision 不能动

```
(10^20+1)-(10^20)
  precision=64 → 1     ✓
  precision=20 → 0     ✗ 算错了，不是显示问题
```

调低它会让大数**真的算错**。它属于"计算层"，不是显示参数。

### displayPrecision 到底管什么

它是**小数点后几位**，不是有效数字。这个区别很实际：

```
12345.678901234
  8 位小数   → 12345.67890123   （保留 8 位小数）
  8 位有效数字 → 12345.679        （只剩 3 位小数）
```

两种都改过，最终按"小数位"实现——因为说"保留 8 位"时人想的是小数位。

### 整数永远完整

```
10^20+5     → 100000000000000000005   （21 位，一位不少）
factorial(50) → 完整整数
```

写成 `1e20` 是**丢信息**，不是简洁。这条是硬约束。

### 小值不会被截断

早先有个真实事故：σ = 5.670374419e-8 在 8 位小数下显示成 `0.00000006`，
**相对误差 5.8%，而数字看起来完全正常**。现在判据是**相对误差超过万分之一就自动转科学计数法**：

```
5.670374419e-8 → 5.67037442e-8
（附提示：按 8 位小数定点显示会丢约 5.81% 的精度）
```

`displayPrecision: 0` 也是合法值——只留整数部分：

```
22/7, displayPrecision:0 → 3
22/7, displayPrecision:1 → 3.1
```

## 三、30 个 operation

### 3.1 求值与代数

| operation | 用途 | 示例 |
|---|---|---|
| `evaluate` | 任意表达式 | `10^20+5`、`factorial(50)`、`5 cm to inch` |
| `solve` | 解方程，逗号分隔 = 方程组 | `3x+2y=10, x-y=1` → `x=2.4, y=1.4` |
| `system` | 显式线性系统 | `matrix=[[3,2],[1,-1]], vector=[10,1]` |
| `derivative` | 符号求导（`order` 指定阶数） | `x^3 * sin(x)` |
| `integral` | 积分：给 `from`/`to` 就是定积分 | `x^2, from:0, to:3` → **9** |
| `simplify` / `expand` | 化简 / 展开 | `2*x + 3*x` |
| `roots` | 多项式求根（含复数） | `x^4 + 1` |

**直觉写法都支持**：`2**10`、`ln(10)`、`log10(1000)`、`π`、`2 × 3`、`6 ÷ 2`。

定积分用 **Fraction 引擎**代入，避开一个精度陷阱：

```
原函数 1/3·x³ 在 x=3 处
  BigNumber → 8.9999999999999999…
  Fraction  → 9
```

BigNumber 的 `1/3` 是截断小数，乘 27 回不到整数。

### 3.2 批量求值

一次算多条，逐条独立报错——**一条失败不影响其它条**。

```json
{"operation":"evaluate","expressions":[
  {"label":"储耗比-中值","expr":"139e8/152e4"},
  {"label":"储耗比-百列","expr":"139e8/1743500"}
]}
```

```
═══ 批量求值（2 条）═══

  储耗比-中值（139e8/152e4） = 9144.73684211
  储耗比-百列（139e8/1743500） = 7972.46917121

成功 2，失败 0
```

**为什么要有 label**：一批十几条时，纯靠顺序对齐会看错行。实测有过"差点引错口径"的事故。

`terse:true` 只回结果，省 token：

```
1/7 = 0.14285714
2^0.5 = 1.41421356
```

**但失败信息绝不隐藏**——失败条照常标出原因，有专门断言守着。

### 3.3 多步计算怎么串（最常用，也最容易踩坑）

**核心事实：批量里按书写顺序执行，前一条的赋值对后一条可见。**
所以多步计算首选「一条 expressions 走完」，不要拆成多次调用。

#### 写法一：批量内链式（推荐）

```json
{"operation":"evaluate","expressions":[
  {"label":"单价","expr":"unit=5"},
  {"label":"数量","expr":"qty=3"},
  {"label":"小计","expr":"sub=unit*qty"},
  {"label":"税","expr":"tax=sub*0.13"},
  {"label":"总计","expr":"total=sub+tax"}
]}
```

```
═══ 批量求值（5 条）═══

  单价（unit=5） = 5
  数量（qty=3） = 3
  小计（sub=unit*qty） = 15
  税（tax=sub*0.13） = 1.95
  总计（total=sub+tax） = 16.95

成功 5，失败 0
```

**关键点**：`sub` 在第 3 条赋值，第 4 条就能直接用。每步都有 label，中间值全可见——
这是多步计算最需要的，因为**能回头核对是哪一步出了问题**。

#### 写法二：单行内联

不需要中间值时直接写成一棵树：

```
((5*3)+(5*3*0.13))  →  16.95
```

优点是一次往返；缺点是没有中间值，算错时不知道哪一段错。

#### 写法三：跨调用传值（变量不自动持久）

**变量只在单次调用内有效**。跨调用要显式传：

```json
{"operation":"evaluate","expression":"total*1.13","variables":{"total":16.95}}
```

或者用工作区变量（见 3.12，需显式打开开关）。

#### 失败会不会级联？

**不会自动级联，但依赖失败步骤的下游会各自报错**——不会悄悄算出一个数：

```json
{"expressions":["a=5","b=oops*2","d=b*2"]}
```

```
  a=5 = 5
  b=oops*2 → 失败[unknown_symbol]：先定义变量，或通过 variables 参数传入
  d=b*2    → 失败[unknown_symbol]："b" 既是变量名也是单位符号

成功 1，失败 2
```

这个行为是**专门修的**：早先 `d=b*2` 不算失败，而是被当成「2 b（单位）」算出
一个合法结果——批量汇总里它显示为**成功**。一个依赖失败步骤的下游悄悄变成
「虚成功」，比报错难发现得多。

#### 三个必须知道的约束

| 约束 | 后果 |
|---|---|
| 变量不跨调用 | 拆成多次调用时，每次要重传 `variables` |
| 单字母中间值可能撞单位 | `b*2`（符号在前）按变量处理；`2 b`（数字在前）按单位。<br>**建议中间值用多字母名**（`sub`/`tax`/`total`），彻底避开歧义 |
| 上限 100 条 | 超了会截断并提示，不是报错 |

> 单字母规则的实际影响：`m`/`V`/`W`/`T` 这类既是物理量惯用名又是单位符号。
> 写成 `m=5` 再 `k=m*2` 是**可以**的（符号在前＝变量）；
> 但只写 `m*2` 而 `m` 从未赋值，会报 `unknown_symbol` 而不是猜它是米。

### 3.4 线性代数与统计

| operation | 用途 |
|---|---|
| `matrix` | 乘法/求逆/行列式/转置/迹；只给 matrix 时输出完整画像（秩/行列式/迹/奇异值/零空间/逆） |
| `eigen` | 特征值与特征向量 |

### 3.5 微分方程

`ode`：RK4 数值解。一阶方程组（SIR / 捕食模型）、二阶方程自动降阶。
返回轨迹、终点值、极值、发散警告。

### 3.6 公式库（404 条）

```json
{"operation":"formula","formula":"escape_velocity","overrides":{"M":1e25,"r":7e6}}
```

```
逃逸速度  [physics/gravity]
表达式: sqrt(2 * G * M / r)
G = 6.6743e-11  (引力常数)
M = 1e+25 *  (天体质量 kg)
r = 7000000 *  (半径 m)
* 表示本次调用覆盖了默认值: M, r
单位: m/s
结果: 13809.21017706 m/s
```

**`overrides` 可以覆盖任何参数**——这是架空世界改造的关键入口。
比如把重力改成 1.5 倍地球：`{"g": 14.71}`。

**拼错的 key 会被点名**，不再静默丢弃：

```
⚠ 以下 overrides 的 key 不在公式「逃逸速度」的参数里，**已被忽略**：mas。
该公式的参数是：G、M、r。若这是拼写笔误，结果可能已偏离。
```

`g`/`c`/`G` 是公式可引用的世界常数，**拿它覆盖不告警**——那是合法用法。

检索用 `formulas`：

```
query="重力"           按名称/关键词
query="layer:derived"  按规则层级
query="domain:物理"    按学科领域
query="freq:high"      按主角感知频率
```

### 3.7 世界推演

`world`：输入星球参数，输出**体感画像**。

```json
{"operation":"world","planetMass":1.5,"planetRadius":1.2}
```

```
══════ 星球体感画像 ══════

【⚠ 先说清楚这些假设】
  · 没有给任何恒星参数，已默认成太阳（G2V，1 L☉，5778 K）。
    若这颗行星绕的不是太阳型恒星（例如 K 型橙星或 F 型巨星），
    温度与宜居带会差很多。
  以下结论都建立在这些假设之上；换掉假设，结论会变。

【最直观的几件事】
  · 表面重力是地球的 1.04 倍——与地球相近，人类体感几乎无差异。
  · 全球平均气温 14°C（地球 15°C）。
  · 地平线距离 5.1km（地球 4.7km）——决定"世界看起来多大"。
```

**注意第一段**：它主动声明了假设，而不是静默替换成太阳。
这条是专门修的——以前传 `F5III`（巨星）会静默回退成 G2V，提示压在 150 行后，
结论可能从"冰封"翻成"熔融"。

参数可写在 `world` 对象里，也可直接写顶层（`{"operation":"world","starMass":10}`）。

### 3.8 改物理常数

```json
{"operation":"constants","constants":{"c":1.5e8}}
```

```
══════ 物理常数推演 ══════

【你直接改动的旋钮】
  c          2.997925e+8 → 1.500000e+8  (↓ 49.97%)

【因耦合而被动改变的量】（不能直接设定，已自动重算）
  mu0        1.256637e-6 → 5.019596e-6  (↑ 299.447%)
  sigma      5.670374e-8 → 2.265013e-7  (↑ 299.447%)
  alpha_fs   0.0072973526 → 0.01…
```

可分**直接旋钮**（c/G/h/kB/e_charge/me/mp/NA/epsilon0）与**派生量**（自动跟随，不能直接改）。

`impact` 跑全部公式算偏差；`quantities` 看哪些量该跟着变、哪些不该。

### 3.9 天体目录与类型学

`bodies`：26 个具名天体 + 32 类天体类型学。

```json
{"operation":"bodies","bodyType":"neutron-star"}
```

```
■ 中子星（Neutron star）  [恒星残骸 · ✓已观测]
  典型质量      1.40 太阳质量
  典型半径      11.0 km
  典型表面重力   1.60e+11 g（地球 = 1）
  典型密度      5.00e+17 kg/m³（水 = 1000）
  依据          已观测（脉冲星）。中子简并压支撑，半径几乎固定。
  读者感知      直径只有 20 公里，却有一点四个太阳的质量。
  一茶匙物质重十亿吨。
  ▶ 物理锁死（编不了）
     中子简并压 + 引力平衡：半径被状态方程锁死在 10—13 km
```

**证据分级是核心**：`✓已观测` / 理论预言 / 纯思辨（戴森球）。分不清这三者就会把
"物理上必然"和"拍脑袋设定"混为一谈。

`bodyConstant` + `bodyFactor` 回答"改了 α 或 G，天体数据哪些该重算"：

```
要重算     ：化学键能 ∝ α²、行星平衡温度
绝不该动   ：行星质量 / 半径 / 轨道半长轴 —— 改了就是篡改设定
```

### 3.10 单位换算（429 条，14 个量纲，度量衡与科学分开）

```json
{"operation":"units","unitValue":30,"unitFrom":"里","unitTo":"km"}
```

```
══════ 单位换算 ══════

  30 里 = 15 km

【代入过程】
  · 1 里 = 500 m
  · 30 里 = 15000 m
  · 1 km = 1000 m，故结果 = 15 km

【注意】
  · 里：市里 = 500 m。周制约 415 m、汉制约 415 m、清制 576 m
    ——写古代按朝代覆盖
```

**给代入过程，不只给结果**——这样能转述给作者看。

#### 429 条，分两类

单位表按**用途**分成两类，列表里也分开列：

| 分类 | 条数 | 例子 | 谁会用 |
|---|---|---|---|
| **度量衡** | 398 | 里/丈/斤/斗、俄尺/日尺/法磅、加仑/英亩、psi/节 | 写小说、算账、历史考据 |
| **科学** | 31 | eV/里德伯/哈特雷、靶恩、玻尔半径、amu、erg、slug | 物理化学天文计算 |

判据是「**作者会不会在正文里写它**」：
`psi` 会（工程题材）所以算度量衡；`hartree` 不会，算科学。
`光年`/`AU` 会出现在科幻正文，**算度量衡**，不算科学。

```
  长度  m     度量衡 100  科学 7   例：m/km/dm/cm/mm/…
  能量  J     度量衡 19   科学 14  例：J/kJ/MJ/GJ/TJ/…
```

展开某一量纲时，**度量衡排在前面**，科学单位单独一段并标明——
找「三丈是多少米」的人不该翻过一堆 eV。

| 组 | 量纲 |
|---|---|

| **电学**（9） | 电流 A / 电荷量 C / 电压 V / 电容 F / 电阻 Ω / 电导 S / 磁通量 Wb / 磁通密度 T / 电感 H |
| **光学**（4） | 立体角 sr / 发光强度 cd / 光通量 lm / 照度 lx |
| **化学与核物理**（5） | 物质的量 mol / 放射性活度 Bq / 吸收剂量 Gy / 剂量当量 Sv / 催化活度 kat |

**七个 SI 基本单位全部到位**（m / kg / s / A / K / mol / cd）——
在此之前缺安培、摩尔、坎德拉，电学光学化学整个领域都换不了。

电学习用示例：

```
   1000 mAh → 1 Ah         12 V → 12000 mV
   2.2 kΩ → 2200 Ω         1 T → 10000 gauss
   1 Ci → 37000000000 Bq   1 rad_dose → 0.01 Gy
   1 sphere → 12.5664 sr   1 sr → 3282.81 deg²
```

**两处刻意处理的坑**：

1. **`rad` 撞名** —— 辐射剂量 `rad`（0.01 Gy）与弧度 `rad` 同名。
   弧度已占用，辐射那条主名是 **`rad_dose`**（别名 `rad (dose)`）。
   否则查 `rad` 永远命中角度。
2. **欧姆两个码位** —— 主名 `Ω`（U+03A9），别名同时收 **`Ω`（U+2126）**。
   不同来源粘贴的文字码位不同，只收一个就有一半认不出。

| `t`（公制吨） | 2204.62 | 1000 |

```
2240 lb → longton   1        2240 lb → shortton  1.12
1 longton → kg      1016.05  1 shortton → kg     907.185
```

自创单位用 `customUnits` 覆盖（如把"里"定成 576 m）。

### 3.11 收支盘点与一致性校验

**`balance`** 回答"这个王国养不养得起二十万兵"：

```json
{"operation":"balance","balance":{"grain":{"demand":2.7e6,"supply":3.1e6,"unit":"kg/年"}}}
```

```
  项目              需求              供给            覆盖    状态
  粮食                  2700000 kg/年      3100000 kg/年    115%   △ 紧

【结论】
  勉强够：所有项都不缺，但粮食只有 115% 余量，一次波动就可能翻到不够。

【最短板】
  木桶效应：整体能撑多大，取决于最紧的这一项。
```

多项一起看，给**最短板**——不是逐项报"够/不够"。

**`feasibility`** 校验单一设定是否物理可行：

```
【校验结果】
  判定            设定值          物理上限        比值    约束
【总判定】
  自洽
  注：经验值类约束有 2~3 倍不确定性，轻微超限可通过在文本中给出解释来消解。
```

注意最后一句：**它不驳回你的设定**，只说明代价。这是本项目一贯的取向——
工具是"说明代价"，不是"教训作者"。

### 3.12 推演栈（derivation，29 个子命令）

把设定拆成可逐步验算的层，并在每层标可信度。

```json
{"operation":"derivation","derivation":"stack"}
```

```
═══ 推演栈（8 层）═══

【M0】元协议层
  核心问题：推演到什么分辨率？给谁看？
  输入：目标 / 范围 / 观测者 / 时间窗口
  下游接口（3 个）：推演卡 / 约束优先级 / 版本规则
  硬约束/失败模式：目标不清会导致无限下钻
```

按用途分组（完整表见 `operation:"help"`）：

| 组 | 子命令 |
|---|---|
| 推演栈 | `stack` `cards` `pipeline` `checklist` |
| 判定 | `dead` `chaos` `flip` `observer` |
| 求解与对比 | `anchors` `backSolve` `sensitivity` `phase` `heatmap` `graph` `timeline` `compare` `diff` |

### 3.13 工作区

一个世界观 = 一套常数表 + 公式表 + 地点 + 变量，**互不污染**。

```json
{"operation":"workspace","action2":"list"}
```

动作：`list` / `show` / `create` / `switch` / `save` / `set` / `add-terrain` /
`delete` / `reset-constant` / `remove-variable` / `reset` / `stats` / `cleanup`

#### 命名变量（新增，默认关闭）

把反复重打的常数存进工作区：

```json
{"operation":"workspace","action2":"set","workspaceVariables":{"BTU_LB":1260000}}
→ ✓ 已更新工作区 "ws"（变量 1 个）
```

**默认不参与计算**。要让它生效，显式打开开关：

```json
{"operation":"workspace","action2":"set","useWorkspaceVariables":true}
{"operation":"evaluate","expression":"BTU_LB/1000"}
→ 1260
```

**优先级**：本次 `variables` 参数 > 工作区变量。

```
variables:{BTU_LB:999000} → 999    ← 临时覆盖
不传                      → 1055   ← 回落到工作区值
```

**为什么默认关闭**：打开后同一调用在不同工作区状态下会给出不同结果，
会削弱"同输入同输出"。这是逐工作区的显式选择，不默认生效。
关闭时变量仍存着，能 show、能删，行为与未引入时完全一致。

**缓存会跟着变量走**：

```
改前 BTU_LB=1260000 → 1260
改后 BTU_LB=1055000 → 1055    ← 不是命中旧缓存的 1260
```

## 四、结果怎么读

### 4.1 可信度标签

| 标签 | 含义 | 能不能写进权威文档 |
|---|---|---|
| `[精确]` | 计算精确，前提假设成立 | 可以，注明假设 |
| `[标度]` | 标度律推算，系数有经验拟合 | 可以，注明是估计 |
| `[量级]` | 只保证数量级 | 只能当量级参考 |
| `[仅方向]` | 只知道变大/变小 | 不能当数字用 |

### 4.2 适用域警告

经验公式会标明三级适用域：

- **无量纲通用**（克莱伯 0.75）
- **形式可泛化但系数需重验**（Fr≈0.4）
- **仅地球成立**（Mifflin 代谢、风寒、Du Bois 表面积等 7 条）

用"仅地球成立"的公式改到外星，输出会附"藏了什么、何时失效"。

### 4.3 假设声明

`world` 会主动声明没给什么、默认成什么（见 3.6 那段"先说清楚这些假设"）。
**这段不是噪音，它决定了这些数能不能引用。**

## 五、什么时候它会拒绝你

| 情况 | 行为 | 为什么 |
|---|---|---|
| `rho=2035; rho*V` | 报 `unknown_symbol` | V 既可能是伏特也可能是变量，不猜 |
| `integral` 给了 from/to | 真的算定积分 | 静默忽略参数最伤信任 |
| overrides 拼错 key | 点名哪些被忽略 | 静默丢弃会让结果"合理但错误" |
| 参数名拼错 | 报 `unknown_argument` | 以前是静默吞掉 |
| `solve` 退化（`x+y=2, 2x+2y=4` | 报 `singular` | 不编一个解出来 |
| 括号不配对 | 给位置 + 层级图 | 只说"检查括号"对长公式等于没说 |

### 单字母变量的特殊规则

物理推演里最规范的变量名恰恰都是单字母（`m`/`V`/`W`/`T`/`g`），
而 mathjs 把 `5 V`（单位）与 `rho*V`（变量）解析成**完全相同的 AST**。
语法层无法区分，只能看上下文：

- **放行**（真单位）：父是乘法且兄弟含数字（`5 V`）、幂指数是数字（`s^2`）
- **报错**：与已定义变量同级（`rho*V`）、或单独出现
- **其它**：放行（纯单位表达式 `9.81 m/s^2`）

```
rho=2035; rho*V  → 失败[unknown_symbol]："V" 既是变量名也是单位符号。
                   若要当单位用，请写成带数字的形式（如 "5 V"）；
                   若要当变量，请先在本次调用里赋值。
```

**已知取舍**：批内混用"变量 + 单位"会被拦（如 `["v=30","9.81 m/s^2 * v"]`）。
这是有意的——报错比猜安全。

### 括号定位（新增）

```
(1+2)/3)
hint: 第 8 个字符处的 ")" 没有对应的左括号
      多数情况是它前面漏了一个 "("

      (1+2)/3)
      0   0
      （数字标的是括号层级，同层级的左右括号应该一一对应）
```

**不做自动补括号**——猜错了会把报错变成一个算错的数，比报错糟得多。

## 六、账本闭合：一个常用配方

没有单独的 `check` operation，用一条 `expressions` 就够，且逐项列值：

```json
{"operation":"evaluate","expressions":[
  {"label":"A","expr":"650*3840"},
  {"label":"B","expr":"200*4745"},
  {"label":"四项和","expr":"650*3840+200*4745+100*3740+50*5120"},
  {"label":"与目标之差","expr":"650*3840+200*4745+100*3740+50*5120-4075000"}
]}
```

差值那项为 0 即闭合。

**为什么不做成 PASS/FAIL**：差 3 和差 3% 是两种情况，压成一个布尔就全糊了。
"差多少"比"是否通过"信息多。

## 七、成本：三处固定开销与各自的分配原则

插件向模型上下文里放东西有**三个渠道**，每个都是每轮重复计费的固定成本。
字数分配原则不同 —— 搞错了就是「钱花了，但模型还是不知道该干什么」。

### 7.1 工具定义（schema）

| 指标 | 现状 |
|---|---|
| 定义总长 | 6228 字符（比基线 7789 省 20%） |

原则：**只写 enum 说不清的事**。30 个 operation 名已在 `enum` 里列全，
description 再列一遍是同一份信息付两次钱 —— 所以 description 只说「怎么选」。

### 7.2 系统提示注入（brief 档，默认）

每轮随上下文下发。**字数按「使用频率 × 重要程度」分配**：

| 内容 | 频率 | 字数 | 理由 |
|---|---|---|---|
| 行为约束（必须调用、不要心算） | 每轮 | ~33 | 决定「调不调」，最重要 |
| **选哪个 operation** | 极高 | ~209 | 最常问的问题，原先一句没写 |
| 可信度标签怎么读 | 中 | ~120 | 决定「这个数能不能引用」 |
| 精度两层 | 中 | ~107 | 调错会算错大数 |
| 世界推演分工 | **低** | ~120 | 只在写架空世界时有用，压到极限 |

合计 **757 字符**（原 817）。

改版时发现三处真实问题：

1. **自相矛盾** —— 原来同时写着「输出默认全精度（几十位小数）」与「默认 8 位小数」，
   两条并列下发，模型读到的是冲突指令。后者是现状，前者是过时表述。
2. **比例失调** —— 世界推演独占 360 字符（44%），而它只对架空世界会话有用。
3. **高频缺口** —— 最常问的「该用哪个 operation」没写，能力清单却罗列了 12 类。

### 7.3 结果缓存

键含常数指纹 + 工作区 + 变量指纹；改设定必然失效。
缓存是「宁可慢不可错」：读不到指纹就给随机值，等于禁用缓存。

### 7.4 三个档位

| 档位 | 长度 | 用途 |
|---|---|---|
| `off` | 0 | 完全不注入（工具仍可用） |
| `brief` | 757 字符 | **默认**，按频率分配 |
| `full` | 3821 字符 | 详细清单，适合需要大量推理的长会话 |

切换方式是 `{promptMode:"full"}`（**不带 operation**）。
返回里给的是**截到 500 字符的预览**，要看全文得走别的接口。

## 八、能力边界：它算不出什么

诚实列出，避免误用：

| 情况 | 为什么 |
|---|---|
| 非线性方程组 | 报 `unsupported`（只解线性） |
| 列表推导式 | 不支持；用 `expressions` 批量 |
| 需要联网核实的外部数据 | **本地执行，不联网**——蓝鲸多重、球团密度这类得自己查 |
| 静默持有隐式状态 | 不做（会破坏同输入同输出） |
| 猜你的意图 | 不做。宁可报错，不猜 |
