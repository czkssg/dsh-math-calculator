# 同类项目深读：怎么做到 / 效果 / 留什么舍什么（2026-11-16）

> 七个仓库已浅克隆到 `.scratch/oss/`（ai-novel 108M、chronicler 32M、kanka 97M、timelines 27M、worldcraft-codex 246M、worldbuilding-dmasad 2.3M、psychohistory 98K）。

## 一、逐个分析

### 1. AI-Novel-Writing-Assistant（3,476★，TS monorepo）

**怎么做**：`client`（Web）+ `desktop`（Electron）+ `infra` + `docs`；pnpm workspace。
世界观作为**设定库**（条目 + 关系），RAG 检索，Agent 编排「规划→逐章写作→检查→保存」。

**效果**：从一句灵感走到完整小说；有独立的 DESIGN_SYSTEM 与 AGENTS.md（给 AI 的工程约定）。

**留**：① **逐章生产状态机**（灵感→大纲→章节→检查）；② 设定库作为 RAG 检索源。
**舍**：编辑器/Electron/云服务/UI——我们是工具不是应用。

### 2. Chronicler（743★，Svelte 离线 wiki）

**怎么做**：设定存成**本地 Markdown 文件**（纯文本），本地索引 + 编辑 UI，无云。

**效果**：离线、可 diff、可用 git 管理。

**留**：**Markdown 为真源**（我们 `novel_outline` 已是）；本地优先。
**舍**：Svelte UI。

### 3. Kanka（368★，PHP/MySQL）

**怎么做**：实体（角色/地点/组织/事件）+ 关系 + 权限 + 公开 API；Vue/jQuery 前端。

**效果**：协作式战役管理，API 可被第三方消费。

**留**：**实体+关系+权限**的数据模型（我们 `topology entities` 已有 20 类实体/14 类关系）。
**舍**：PHP 栈、MySQL、多租户。

### 4. Timelines（245★，JS）

**怎么做**：事件/年代数据结构 + 缩放时间轴交互。

**留**：时间线数据形状（事件含 start/end/lane）。
**舍**：交互 UI（我们只有 `timeline_check` 校验）。

### 5. Worldcraft Codex（104★，JS 本地桌面）

**怎么做**：一个工程里放 World Wiki、设定条目、长篇小说、任务线、分支剧情、**互动地图、关系图谱、时间线、资源库**、AI 连接——**多视图共享同一数据模型**。

**效果**：作者工作台（截图见 docs/images）。

**留**：**多视图共享数据模型**这个设计（我们数据层已是 JSON，天然支持）；分支剧情/任务线的状态建模。
**舍**：Electron/UI/资源库。

### 6. dmasad/WorldBuilding（48★，Python/Jupyter）

**怎么做**：**模型级联**：
```
TerrainGenerator → NomadModel → TributeModel → TributeNarrative
```
- `NomadModel`：部落按 `water(1000×流量) + slope(1/坡度) + elevation(10×(1−海拔))` 加权随机移动；
- `TributeModel`：**Axelrod (1995) 贡赋模型**——wealth（财富即权力）、commitment（承诺度）、coalition（联盟）、war（战争），关系随纳贡上升、随敌对下降；
- `TributeNarrative`：把模拟结果写成叙事。

**效果**：生成世界地图 + 历史（见 Cities.png 与 Model demo.ipynb）。

**留**：① **模型级联 + 每步明确的输入/输出**（我们模型链正是这个，本轮加了自动排序）；② 两个可移植的模型（加权移动、贡赋/联盟/战争）；③ **随机种子**保证可复现。
**舍**：Python/networkx 实现、Jupyter。

### 7. Project Psychohistory（9★，纯 prompt 协议）

**怎么做**：`Psychohistory_Agent.md` 是一份**协议**：
- 状态机：`INITIALIZING → AWAITING_DECREE → SIMULATING_ERA`；
- 每轮五阶段：`LOGIC（算数值）→ IMAGINE（写叙事）→ COINCIDE（查危机触发）→ DIVERGE（悖论）→ SYNTHESIZE（编年史）`；
- **确定性 PRNG**：LCG（`1664525 / 1013904223 / 2^32`），seed = `len(history_log)×pop + year`，保证同状态同结果；
- 状态量：`pop / stability / res / tech / cult`（各带 tier 与 val）。

**效果**：给一个初始文明 → 逐年推演 → 生成历史事件与叙事。

**留**：① **LCG 确定性 PRNG**（我们没有！）；② **状态机 + 阶段化 cycle**（历史推演的骨架）；③ 状态量五元组（人口/稳定/资源/技术/文化）。
**舍**：prompt 注入式执行（我们是可执行工具，不由 AI 充当引擎）。

## 二、汇总：留 / 舍

| 项 | 决定 | 理由 |
|---|---|---|
| 逐章生产状态机（ai-novel） | ✅ 留思路 | 与我们的「分阶段推演」一致 |
| Markdown 为真源（chronicler） | ✅ 已有 | novel_outline 已是 |
| 实体+关系模型（kanka） | ✅ 已有 | topology entities |
| 时间线数据结构（timelines） | ⚠️ 可选 | 需要时加，不做 UI |
| 多视图共享数据模型（worldcraft-codex） | ✅ 留思路 | 我们的 JSON 数据层天然支持 |
| **模型级联 + 自动排序**（WorldBuilding） | ✅ **已落地**（模型链 + orderSteps） | 本轮做 |
| **确定性 PRNG（LCG）** | ✅ **建议做** | 我们没有；推演要可复现 |
| 贡赋/联盟/战争模型（Axelrod） | ⚠️ 可选 | 可做成 `conflict` 公式/模型 |
| 五阶段 cycle（psychohistory） | ✅ 建议做 | 历史推演的骨架 |
| UI / Electron / 编辑器 / 云服务 | ❌ 舍 | 我们是工具，无界面 |

## 三、下一步（按收益排序）

1. **确定性 PRNG（seed）**：给所有随机类推演加 seed，锁住「同输入同输出」——这是我们已有的不变量，但随机模块还没保证。
2. **历史推演（history）**：状态机 + 五阶段，给初始文明 → 推演 N 年 → 事件序列。
3. 贡赋/联盟/战争模型（Axelrod）作为 `conflict` 模型。

## 四、二次加工：原料 → 我们的模块（已落地）

> 原则：**不直接用**。开源实现带着 Python/numpy/UI/prompt 假设，必须改成我们的契约（JS、result/notice、CalcError、无界面、确定性）。

### 1. Project_Psychohistory 的 LCG → `src/core/prng.ts`

| 原版 | 二次加工后 |
|---|---|
| seed 公式写死在 prompt 里：`len(history_log)×pop + year` | `seedFrom(...parts)` 用 FNV-1a 混合任意分量，避免相加碰撞 |
| 只有 `roll` 到 [0,1) | 加 `rollInt(min,max)`、`createPrng` |
| 只在 prompt 协议里用 | 成为通用模块，任何随机推演都能用 |

**验证**：同种子同序列（可复现）、不同种子不同、取值区间正确。

### 2. WorldBuilding 的 extrema + TributeNarrative → `src/features/deduction/history.ts`

| 原版 | 二次加工后 |
|---|---|
| `extrema.py` 用 numpy 找极值，按窗口重要性排 | 纯 JS 局部极值 + 相对振幅阈值 |
| `TributeNarrative`「两个极值之间算一个纪元」 | `buildEpochs`：纪元 = 极值间区间，含 rise/fall/flat 与事件归属 |
| 名字生成器 + matplotlib 画图 | 不做（无界面；只输出结构） |
| 无最小长度，噪声会切碎 | 加 `minEpochYears` 过滤 |

**验证**：20/40/60 转折年检出、事件归入正确纪元、高频噪声不切碎。

### 3. 尚未落地的原料（排在后面）

| 原料 | 还需什么才能用 |
|---|---|
| Axelrod 贡赋/联盟/战争模型 | 需要「行动者网络 + 承诺度矩阵」的数据模型（我们 topology org 已有雏形） |
| Voronoi 地图分区 | 需要 2D 坐标与多边形（我们是节点/边，无多边形） |
| 五阶段 cycle（LOGIC→IMAGINE→…） | 需要「历史推演」的状态机（下一步） |
| ai-novel 逐章状态机 | 需要「章节生产」流程（属写作层，非本工具） |
