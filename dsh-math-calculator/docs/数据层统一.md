# 数据层统一：第五处收敛完成（2026-11-16）

> 用户要求：全量耦合、功能重复合并。数据管理从「五处各自存储」收敛为「一个数据层」。

## 一、收敛结果

| 数据 | 原来存哪 | 现在 |
|---|---|---|
| 变量 / 常数 / 自定义公式 / 实体类型 | `workspace-state.json` | `data`（kind: var/constant/formula/entity-type） |
| 世界设定库 | `<ws>.state.json` | `data` kind:"setting" |
| 推演归档 | `<ws>.derivation.json` | `data` kind:"archive" |
| **拓扑模型** | `workspace-state.json` 的 `topologyModels` | **`data` kind:"model"** |
| 运行日志 | `logs/run.log.jsonl` | 保留独立（旁路，不该进数据层） |

## 二、统一后的存储

    <workspace>/.artifacts/datastore/
      records.jsonl      ← append-only（每行一条记录，可 grep/diff）
      records.jsonl.bak  ← compaction 旧档

所有数据都能被同一套动作访问：`put/get/query/search/lineage/stats/export/import/compact/migrate`。

## 三、迁移兼容

每个合并点都保留「旧文件首次导入」：

- 设定库：数据层为空 → 读 `<ws>.state.json` 并导入；
- 归档：数据层为空 → 读 `<ws>.derivation.json` 并导入；
- 拓扑模型：`migrateLegacy()` 从 `workspace-state.json` 的 `topologyModels` 导入（kind=model）。

## 四、合并中踩到的三个坑（都是隐含契约）

| 合并 | 破坏了什么 | 修法 |
|---|---|---|
| 设定库 → data | `listStateWorkspaces`（依赖目录扫描） | 列表改从数据层取 |
| 归档 → data | **版本顺序**（依赖数组插入序） | 读取时按版本号升序排序 |
| 拓扑模型 → data | 无（save/load/list 直接换源） | — |

**教训**：存储合并不是「换个地方写」，而是「保证读出来的顺序与形状不变」。
