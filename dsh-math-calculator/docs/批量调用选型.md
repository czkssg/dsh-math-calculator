# 批量调用选型（calls）

> 2026-11-18 · 用户要求：「提一下工具所有的功能。批量调用的都改成批量调用。别让 AI 一个一个调用功能。」

## 一、需求

工具 62 个 operation，其中真正支持批量的只有 3 处：

```
evaluate.expressions[]      数值批量（逐条独立报错，带 sanityStatus）
formulas.formulas[]         公式批量（每条可 overrides/label）
data.dataJson               导入批量
```

其余 59 个 operation 一次只能交一条。AI 要比较 5 组单位换算、5 个星球的气候，就得发 5 次工具调用，
每次都要付完整 schema + 一次往返 + 一条结果。这就是用户说的「一个一个调用」。

## 二、开源调研（AGENTS.md 开工前硬门槛）

| 来源 | 结论 |
|---|---|
| MCP 规范 2025-06-18 `schema.ts`（42 KB，实测抓取，`batch` 命中 0） | **协议层没有批量**：一次一条 `tools/call` |
| MCP 规范 2025-11-25 `schema.ts`（66 KB，`batch` 命中 0） | 最新版仍未引入 |
| JSON-RPC 2.0 规范（jsonrpc.org） | 有 batch：请求为数组、**逐条独立响应**、一条失败不影响其它 |
| 模型 API 的并行 tool call（OpenAI/Anthropic 等） | 只解决「一次请求发多个 call」；每次仍各付一次 schema，插件无法控制 |

**结论**：没有可直接复用的批量执行层（协议层不做，工具层各做各的）。
本项目在**参数层**做，改动最小，且与既有 `expressions`/`formulas` 一脉相承。

## 三、设计

```jsonc
{ "calls": [ {"operation":"units","unitFrom":"担","unitTo":"kg"},
             {"operation":"evaluate","expression":"1/3"} ] }
```

- **不新增 operation**：新增会牵动 enum（62→63）、help 节数、三个门面的分组与 skill 计数；
  `calls` 是工具参数，四处清单一处都不动。
- **语义对齐 JSON-RPC batch**：按数组顺序执行（后一条可以用前一条的结果，由调用方自行安排）；
  逐条独立响应；一条失败不中断；顶层 `ok` 表示「全部成功」，`partial:true` + `failed`/`succeeded` 给计数。
- **三条硬约束**：
  1. 条目不能再含 `calls`（无限套娃 → 该条直接 `invalid_argument`）；
  2. 单次上限 **50 条**（一次结果直接进上下文，再多请拆批）；
  3. 外层只继承 `precision`/`displayPrecision`（别的键会污染每条，如 `expression`）；
     `saveAs` 必须在条目里，外层写了会被忽略并 `notice` 说明。
- **未知 operation 在本地拦**：条目参数不走宿主 schema 校验，不查会落进老入口被翻成 `internal`
  （看起来像工具 bug）。
- **渲染兜底**：部分失败时顶层 `ok=false`，常规渲染只显示一行 error；
  批量在 `value.results[]` 存在时优先输出分段文本，逐条结果与 notice 都不丢。

## 四、取舍：为什么保留 expressions / formulas

`calls` 是通用兜底；`expressions`/`formulas` 是**专用批量**：每个条目更短（不必重复 operation），
且带该领域特有字段（sanity / overrides / label）。两者并存：日常优先专用，跨 operation 用 `calls`。

## 五、验证

`test-v3/tool-batch.mjs` 41 项：批量结果与单条**逐字等价**、顺序一致、部分失败计数与 partial、
未知 op / 嵌套 / 空 / 超限、precision 继承与覆盖、外层 saveAs 忽略、部分失败渲染、world 的 notice 保留。

## 六、没有做（诚实边界）

- 不做并行执行：条目之间可能共享工作区状态（写入常数、建表、saveAs），并行会让结果依赖调度顺序；
- 不做「一条失败即中止」（与 JSON-RPC batch 一致，但若需要严格事务，调用方自己分两次发）；
- 不把条目结果按 operation 自动合并成表格：那属于上层呈现，工具只保证数据通道完整。
