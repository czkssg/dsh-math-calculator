# R51 极端测试解读（2026-11-17）

> R51 报 53 项极端用例 28 通过 / 25 失败（52.8%），核心指控是「25 个只回一句 `[object Object]`」。

## 一、先核一件事：`[object Object]` 我复现不出来

我逐条跑了附录里全部 25 个用例，**每个的 `error` 都是完整结构**、`result` 都是可读文本：

```
1/0        → result: "错误[non_finite]: 结果不是有限数（表达式：1/0）"
             error:  {type:'non_finite', message:'…', hint:'常见原因：除以 0、对数里…'}
eigen非方阵 → result: "错误[invalid_argument]: 特征值只对方阵有定义（收到 2×3）"
system矛盾  → result: "错误[singular]: 方程组解不唯一（系数矩阵奇异…）"
```

R51 附录自己贴出来的 `error` 字段也是完整的——所以「只回一句 `[object Object]`」
应该是**宿主那一侧拼装错误消息时**把对象 `String()` 化了，不是工具返回值的问题。
（也可能是旧构建；我这一轮的改动要重启才生效。）

## 二、真正复现到并修掉的 4 个

| # | 缺陷 | 之前 | 现在 |
|---|---|---|---|
| 1 | **空表达式假成功** | `ok:true`、`result:"undefined"` | `missing_params: 表达式为空` |
| 2 | 深嵌套/超长 | `internal: Maximum call stack size exceeded`（跑偏） | `invalid_argument: 表达式太复杂，解析时栈溢出` + 拆解办法 |
| 3 | 超长表达式灌爆消息 | 5000 字符原文进 `message` | 截断为「前 40 字…（共 N 字符）」 |
| 4 | `sensitivity` 静默默认 | 空输入也用内置模型，不吭声 | 明说「用的是内置默认模型」 |
| 5 | `interval` 反序静默交换 | `[20,6]` → `[6,20]`，不提示 | 报错：上下界写反了 |
| 6 | **中文大写数字全盲** | `壹仟贰佰` 抽不到；主体被切成「部壹」 | 1200 ✓、主体「部」✓、冲突报得出 |

## 三、第 6 条有两层，第二层更隐蔽

**第一层**：`parseChineseNumber` 只认 `一二三`，不认 `壹贰叁`。
**第二层**：中文数字本身就是汉字，落在主体字符集 `[\u4e00-\u9fa5]` 里——

```
部壹仟贰佰人  →  主体被抽成「部壹」   ← 数字吃进了主体
部八百至一千人 →  主体被切成「部八」「至一」
```

只补第一层，数值对了但主体全错、照样报不出冲突。
修法：主体用「**非数字汉字**」的 1–6 字（`(?:(?![数字汉字])[\u4e00-\u9fa5]){1,6}?`）。

## 五、没修的（需要你确认）

| 项 | 为什么没动 |
|---|---|
| `(-8)^(1/3)` 报 non_finite | 数学上负数的分数幂在实数域确实无定义（主值是复数）。现在的提示说「检查分母与函数定义域」，够用；要更贴切可加一句「负数开奇次方请用 -(8^(1/3))」。 |
| `[object Object]` | 复现不出，怀疑是宿主侧或旧构建 |
