## 二、本轮三项改动

### 1. 表达式上限：三道闸

原文档只写「10000 字符」，但解析是递归的——**项数与嵌套深度先于字符数撞栈**（实测 4950 项、1000 层括号）。

现在引擎按顺序拦：

```
① 字符数 > 10000     → invalid_argument「超过字符上限」
② 运算符 > 2000 个   → 「表达式过长：约 N 个运算符」
③ 括号嵌套 > 200 层  → 「表达式嵌套过深」
```

help 的 evaluate 节与 SKILL 边界表都写明这三条，做到「文档与实测一致」。

### 2. 性能预警

单次调用 ≥2s 时，结果 notice 追加：

```
本次耗时 5.3 秒（规模较大）；这是正常等待，不是卡死。要更快请减小规模或分批。
```

批量外层不重复报（各条会各自报），避免一段结果里 N 条同样提示。

### 3. 公式分项（parts）

公式数据可声明中间项：

```json
"parts": [
  { "label": "p²", "expr": "p^2" },
  { "label": "2pq", "expr": "2*p*q" },
  { "label": "q²", "expr": "q^2" }
]
```

渲染时附「分项：…」，`value.parts` 给结构化三项。哈温是第一个用例（最常算的正是 2pq=携带者比例）。
