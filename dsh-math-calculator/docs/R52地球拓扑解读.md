# R52 地球拓扑解读（2026-11-17）

> R52 报：9/9 子命令在地球图上全部通过，但「脏图」4 类非法输入全崩成 `[object Object]`。

## 一、先说结论：4 类里 3 类已经修好了

R52 测的是旧构建。我在当前构建下逐条复现：

| # | 用例 | R52 报 | 当前实际 |
|---|---|---|---|
| 1 | 自环 `A→A` | `[object Object]` | **`invalid_argument: 自环边：A`** ✓ |
| 3 | 点 id 重复 | `[object Object]` | **`invalid_argument: 节点 id 重复：A`** ✓ |
| 4 | 悬空边 `A→X` | `[object Object]` | **`unknown_symbol: 边指向不存在的节点 X`** ✓ |
| 2 | **反向重复 `A→B` + `B→A`** | `[object Object]` | ✗ **真崩**：`internal: Graph.addEdge: an edge linking "B" to "A" already exists` |

## 二、唯一的真崩：反向重复

### 根因

边默认 `bidirectional: true`，去重键却是**有向**的：

```js
const key = from + '|' + to      // A|B 与 B|A 是两个键
```

于是两条边都进了 `graph.addEdge`；而无向图里它们本就是同一条边，graphology 直接抛异常。

这个异常没有 `type`，被归成 `internal`——**看起来像工具 bug，实际是输入重复**。

### 修法

去重键按**无向**取（除非两端都显式声明单向）：

```js
const isOneWay = raw.bidirectional === false
const key = isOneWay ? from + '|' + to : [from, to].sort().join('|')
```

现在第二条会变成一条 `duplicate_edge` 提示，而不是崩溃。

## 三、两个静默边界（都修了）

| 用例 | 之前 | 现在 |
|---|---|---|
| 节点无 `lon/lat` | 总长 **0.0 km**，无声 | 明确提示「两端缺坐标，长度按 0 处理——总长不可信」 |
| 经纬越界（lat 200 / lon 400） | 算出 **15,127 km** | `invalid_argument: 节点「A」的 lat 越界：200` |

越界这条尤其危险：haversine 对超范围输入不会报错，会给出一个**看似合理的距离**——
作者只会觉得「这个数字怪」，不会想到是经纬度写错了。
