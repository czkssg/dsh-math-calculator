# 第二部分：该换成开源的部分（逐个核实）

## 2.1 已用开源、无需换的

| 能力 | 现用库 | 判断 |
|---|---|---|
| 表达式求值/符号微积分 | `mathjs` 15.2 + `algebrite` 1.4 | ✅ **已在用**。符号积分靠 algebrite（mathjs 无此能力） |
| 大数精度 | mathjs `BigNumber` | ✅ 已在用 |

**一处要说明**：`algebrite` 在 `symbolic.ts` 里**确实在用**（通过 `A.eval`），
不是"引入未使用"。此前我误判过一次，已核实。

## 2.2 手写但该换的（3 类，共约 1,100 行）

### ① 统计分布 → `jstat`（v1.9.6，**160 万周下载**）

**手写现状**（`stats.ts` 409 行）：

```
logGamma / erf / normalCdf / normalInv / binomialCoefficient
binomialPmf / binomialCdf / poissonPmf / poissonCdf
exponentialCdf / chiSquareCdf / regularizedGammaP / studentTCdf
```

这些是**教科书级的实现**，而 `jstat` 已把这些做了十几年：

| 我们的函数 | jstat 对应 |
|---|---|
| `normalCdf` / `normalPdf` / `normalInv` | `jStat.normal.cdf/pdf/inv` |
| `binomialPmf` / `binomialCdf` | `jStat.binomial.pdf/cdf` |
| `poissonPmf` / `poissonCdf` | `jStat.poisson.pdf/cdf` |
| `exponentialCdf/Pdf` | `jStat.exponential.cdf/pdf` |
| `chiSquareCdf` | `jStat.chisquare.cdf` |
| `studentTCdf` | `jStat.studentt.cdf` |
| `erf` / `logGamma` / `regularizedGammaP` | 内部实现，jstat 不导出（保留） |
| `quantile` | `jStat.percentile` |
| `describe` | `jStat.mean/stdev` 组合 |

**风险**：`jstat` 是 UMD 老式包，ESM 导入需要 `import jstat from 'jstat'` 或
`createRequire`。且它**不做线性代数**（`solveLinearSystem` 要另找）。

### ② 线性代数 → `ml-matrix`（v6.15.1，**197 万周下载，MIT，24 天前更新，2 个依赖**）

**手写现状**（`numeric.ts` 268 行）：

| 我们的函数 | 调用数 | ml-matrix 对应 |
|---|---|---|
| `rref` | 2 | 无直接对应，但可由 LU/QR 推导 |
| `rankOf` | **6** | 用 SVD 的奇异值非零个数 |
| `nullspaceOf` | **5** | 用 SVD 的右奇异向量 |
| `singularValuesOf` | **8** | `new SVD(A).diagonal` |
| `solveLinearSystem` | 5 | `solve(A, B)` + `inverse(A, useSVD=true)` |

**ml-matrix 明确提供的**（读自官方 README）：

```
inverse(A, useSVD=true)      ← 奇异矩阵也能求（我们手写的正好缺这个）
pseudoInverse()              ← 伪逆
solve(A, B, useSVD)          ← 最小二乘
QrDecomposition / LuDecomposition / CholeskyDecomposition
EigenvalueDecomposition      ← 已有 eigen 操作可用
linearDependencies()         ← 行间线性依赖
```

**这是最大的一块收益**：`singularValuesOf` 被调用 8 次、`rankOf` 6 次、`nullspaceOf` 5 次，
全部可以换成 `SVD` 一个分解。

### ③ ODE 求解 → 候选待定

**手写现状**（`ode.ts` 462 行）：自己实现了 RK4 + 刚性检测。

**候选**：

| 库 | 判断 |
|---|---|
| 无成熟 JS ODE 库 | ⚠️ 搜过，`ode-rk4`、`ode45` 等都是玩具级（无维护、无刚性检测） |
| 自己写 RK4 | **可保留**——RK4 是 30 行教科书算法，难点在**刚性检测与步长控制**，那才是我们手写的价值 |

**结论：ODE 不换。** 理由：开源无可用的成熟实现，而我们的刚性检测（`N12` 警告）
是真实价值。

# 第四部分：工作计划的四阶段

## 阶段 0：备份与基线（0.5 天）

```
① 打 tag：refactor-baseline-2026-11-12
② 记录当前全量测试结果（134 套 / 6,702 项）
③ 记录关键输出快照（20 个代表性调用的完整返回）
   —— 用于重构后逐字比对，证明"行为未变"
```

**为什么先做这个**：重构最大的风险是"悄悄改了行为"。
有 6,702 项测试 + 20 个快照，才能证明没改坏。

## 阶段 1：线性代数换 ml-matrix（1 天）

**为什么先做这个**：调用量最大（SVD 8 处、rank 6 处、nullspace 5 处），
且 ml-matrix 与现有代码的接口最接近。

```
① 加依赖 ml-matrix
② 新写 numeric-ml.ts，用 ml-matrix 实现 5 个函数（保持签名不变）
③ 逐函数切换：先切 singularValuesOf（调用 8 处），跑全量测试
④ 再切 rankOf / nullspaceOf / rref
⑤ 对比新旧实现的数值输出（同输入必须同输出，容差 1e-10）
⑥ 删旧实现
```

**验收**：134 套全绿 + 20 个快照逐字相同。

**额外收益**：`inverse(A, true)` 走 SVD，奇异矩阵也能求。
这会让 `solve` 能区分「无解」与「无穷多解」—— **顺带修掉反馈包 A5**。

## 阶段 2：统计分布换 jstat（1 天）

```
① 加依赖 jstat
② 新写 stats-jstat.ts，映射 12 个分布函数
③ 保留 erf / logGamma / regularizedGammaP（jstat 不导出）
④ 对比新旧（容差 1e-12，因为是解析函数）
⑤ 逐函数切换 + 跑测试
```

**风险点**：`jstat` 是 UMD，ESM 下要用 `createRequire` 或默认导入。
这一步要先写一个小探针验证导入可用，再动主代码。

**若 jstat 导入不顺利**：备选 `@stdlib/stats`（Apache-2.0，但依赖链大），
或干脆保留手写（它们本来是对的，只是没经过社区验证）。

# 第五部分：必须守住的四条边界

## 5.1 行为不许变

重构的定义是"**对外行为完全不变，只换内部实现**"。

```
判据：6,702 项测试全绿 + 20 个快照逐字相同
若有不一致 → 先证明哪边是对的，不许"以新的为准"糊过去
```

## 5.2 中文单位表不换

UCUM 没有「里/丈/亩/时辰/贯/石」，必须自建。
`ml-matrix` 与 `jstat` **都不涉及单位**，所以两者不冲突。

## 5.3 精度语义不降级

本项目用 `BigNumber` 保精度，而 **jstat 与 ml-matrix 都是双精度浮点**。

```
风险：把 BigNumber 路径换成 jstat，会让 (10^100+1)-(10^100) 这类算错
对策：统计与线性代数本来就是浮点域（没人用 100 位精度算 t 检验），
     但 matrix/eigen 的 BigNumber 路径要保留，只在必要处用 ml-matrix
```

**这条必须逐函数确认，不能一刀切。**

## 5.4 不开工就写清"为什么不开工"

被否决的候选要留档：

| 候选 | 为什么不换 |
|---|---|
| `@stdlib/stats` | Apache-2.0 可用，但依赖链 ~20 个包，收益不如 jstat |
| `graphology` | 当前无可换的图算法（`dependency` 是刚写的） |
| `@turf/turf` | 空间拓扑尚未实现，等实现时再引 |
| ODE 库 | 无成熟实现，自己写的刚性检测是价值 |

# 第六部分：三个前提已实测（2026-11-12）

## 6.1 ✅ `jstat` 在 ESM 下可用（已实测）

装到临时目录跑通，**零依赖、1.1M**：

```js
import jstat from 'jstat'   // 默认导入，不是命名导入
jstat.normal.cdf(1.96, 0, 1)     → 0.975002   ✓
jstat.studentt.cdf(2, 10)        → 0.963306   ✓
jstat.chisquare.cdf(3.84, 1)     → 0.949956   ✓
jstat.poisson.cdf(2, 3)          → 0.423190   ✓
jstat.binomial.cdf(3, 10, 0.5)   → 0.171875   ✓
jstat.normal.inv(0.975, 0, 1)    → 1.959964   ✓
```

**一个坑**：`jstat.percentile()` 返回结构与我们手写不同（需 `.slice()`），
不是直接返回数。切换时要单独注意。

## 6.2 ✅ `ml-matrix` 可用，但 **README 有误导**（已实测）

装好验证，**5 个包、1.2M**：

```js
import { Matrix, SVD, inverse, pseudoInverse, solve } from 'ml-matrix'
```

**README 里写的 `A.pseudoInverse()` 是错的** —— `Matrix` 实例上没这个方法。
真实做法是**顶层函数** `pseudoInverse(A)`。

实测结果：

```
SVD 奇异值          [16.848, 1.068, 0.000]  → 秩 2（正确）
pseudoInverse(A)    3×3                      ✓
inverse(A, true)    3×3（走 SVD）            ✓
inverse(A)          抛错「LU matrix is singular」  ← 符合预期
solve(2×2, b)       [1, 3]                   ✓
```

**最有价值的一条**：`inverse(A, true)` 走 SVD，**奇异矩阵也能求**。
我们手写的 `solveLinearSystem` 在奇异时只报 `singular` 就结束了 ——
这正是反馈包 `A5`（无解与无穷多解混为一谈）的根因。

**换 ml-matrix 会顺带修掉 A5。** 这是重构的额外收益。
