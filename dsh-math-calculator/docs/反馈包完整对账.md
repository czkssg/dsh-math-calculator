## 五、优先级建议（按影响面重排）

| 优先 | 项 | 理由 |
|---|---|---|
| **1** | A24 `(10^100+1)-(10^100)=0` | **默认参数下静默丢精度**，而本项目以精确计算立身 |
| **2** | T8-D02/D04 精度旋钮 | 用户按文档设 `displayPrecision=0` 会拿到错的数 |
| **3** | T4-15 批量吞未知 key | 批量是最常用路径，拼错参数静默忽略 |
| **4** | T7-N1/N10/D4 `balance`/`dist` 不校验 | 输入错也不报，输出看着正常 |
| **5** | T5-N1 / derivation 契约族（~10 条） | `ok=true` 却什么都没算，自动化流水线会误判 |
| **6** | A5 `solve` 语义 | 已有 `singular`，但分不出「无解」与「无穷多解」 |
| **7** | W21-T03 / A2 上标 | 已立规划（复合单位），属系统性重做 |
| **8** | 其余 37 条未测项 | 先测完再排 |

**第 1 条最要紧**：`(10^100+1)-(10^100)` 在默认 `precision=64` 下返回 0，
而同一工具的 `10^100+1` 能完整输出 101 位整数 —— **显示层能存，运算层存不住**。
这与本项目「精确」的立身之本直接冲突。
