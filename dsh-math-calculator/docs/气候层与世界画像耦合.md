# 气候层与世界画像耦合（2026-11-16）

> 用户要求：补气候层（温度带、降水、雨影），并把世界观画像与地图耦合。

## 一、不重复实现（重要）

`features/deduction/climate.ts` **已存在**，含精确模型：

| 函数 | 作用 |
|---|---|
| `annualMeanTemperature(lat, globalMeanK, greenhouseK, pressureAtm)` | 纬度 + 温室 + 气压 → 年均温 |
| `computeSeason` / `noonElevation` / `dayLength` | 季节与日长 |
| `climateZone(lat, tempC, hasLiquid, annualRangeK)` | K 类分区 |

所以新模块是 **`grid-climate.ts`（网格适配层）**，不是重写：
逐格调用现有函数 + 补降水（原文件没有降水）。

**踩的坑**：第一版我直接写了 `climate.ts`，把原文件覆盖了——编译立刻报
`world.ts` 找不到 `computeLayeredClimate`。已 `git checkout` 恢复。

## 二、气候层算什么

| 量 | 算法 |
|---|---|
| 温度 | `annualMeanTemperature` + 海拔递减 6.5 K/km（海拔 = 海平面以上相对高度 × 2500 m） |
| 降水 | ITCZ/副高/极锋三带 + 距海衰减（60 mm/格，上限 600）+ 迎风坡地形雨 − 背风坡雨影 |
| 分区 | `climateZone`（温带 60% 可耕、亚热带 45%、热带 40%、针叶林 15%、沙漠 1%、苔原 2%） |
| 可耕率 | 分区面积加权（球体按 cos lat） |

## 三、耦合链

```
world（物理画像）
  → world-map（地形 + 海陆 + 河流 + 矿产 + 国家）
  → grid-climate（温度 + 降水 + 分区 + 可耕率）
  → world-build（承载力 = 可耕面积 ÷ 人均耕地）
```

调用：

```jsonc
{ "operation":"world-map", "climate":true, "mapWidth":180, "mapHeight":90, "seed":7 }
{ "operation":"world-build", "useMap":true, "mapSeed":7 }
```

实测（地球参数）：

| 可耕率来源 | 可耕率 | 承载力 |
|---|---|---|
| 固定 10% | 10.0% | 14.8 亿 |
| **地图 + 气候** | **46–53%** | **68–78 亿** |

气候分区（seed 7）：温带 30%、亚热带 48%、温带寒 13%、冻土 6%、针叶林 2%。

## 四、精度边界（说清楚）

- 温度：不做大气环流求解；倾角影响季节但网格是年均；
- 降水：三带 + 地形 + 距海，**没有**季风、洋流、云物理；
- 可耕率是「**潜在**可耕」（温带 60%），现实耕地约占陆地 12%——两者不是一回事。
