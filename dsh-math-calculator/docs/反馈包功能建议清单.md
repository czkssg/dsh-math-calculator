# 二、`06` 号 P0 八项（强烈建议）

## N1 · 台账闭合器 `ledger`

**原始要求**：
```
{operation:'ledger', ledger:{parts:[{name:'士',value:1},...], total:100}}
→ 分项之和 99.011%，差 0.989%，最可疑：贵族（0.01 → 应为 1）
```

**为什么**：W02 占比合计 99.011%、W13 分项 6300 ≠ 自称 5500、W12 伤亡上限和 119%。
**反馈包统计：282 条硬伤里 139 条（48%）是账本闭合。**

**当前状态**：✅ **已实现**。实测能复现 W02（99.011% → 指出「贵族疑似差 100 倍」）

---

## N2 · 数字抽取器 `extract_numbers`

**原始要求**：
```
{operation:'extract_numbers', text:'…正文…'}
→ 每条 {raw, value, unit, context, line}
```

**为什么**：整理 23 份 PDF 时，**22,115 行台账是用 Python 脚本抽的**。
「40% 的工作量在这里，工具零支撑」。

**当前状态**：✅ **已实现**。中文量级折算、噪音过滤、区间、上下文齐全。

---

## N3 · 多义单位消歧 `units_ambiguous`

**原始要求**：
```
{operation:'units_ambiguous', term:'里'}
→ {candidates:[{unit:'里',value:500,note:'市里'},{unit:'里',value:201,note:'英里'}], pick:'需指定'}
```

**为什么**：「里」在中文里是市里（500 m）还是英里（1609 m）？「石」是容量还是重量？
**架空设定里这种歧义天天出现。**

**当前状态**：❌ **缺失**。现在只有 `units` 的精确匹配，不处理多义。

---

## N4 · 精度预算检查 `precision_check`

**原始要求**：
```
{operation:'precision_check', expression:'(10^100+1)-(10^100)', precision:64}
→ {ok:false, need:101, have:64, hint:'这次运算需要 101 位有效数字'}
```

**为什么**：A24 `(10^100+1)-(10^100)` 在默认 precision=64 下返回 0。
用户不会预先知道要调精度。

**当前状态**：❌ **缺失**。（A24 本身也仍未修）

---

## N5 · 结构化输出 `format:'json'`

**原始要求**：
```
{operation:'evaluate', expression:'1+1', format:'json'}
→ 只回 JSON，不回人类可读文本
```

**为什么**：自动化流水线要解析结果，现在只能正则从文本里抠。

**当前状态**：❌ **缺失**。传了报 `unknown_argument`。

---

## N6 · 回执清单 `manifest`

**原始要求**：
```
每次调用附：{manifest:{operation, args, formulasUsed, constants, workspace, cacheHit}}
```

**为什么**：事后无法回答「这个数是用哪些参数/公式算的」。

**当前状态**：❌ **缺失**。

## N7 · 会话隔离 `sessionKey`

**原始要求**：

```
→ A 与 B 各自的工作区互不影响
```

**为什么**：A1 报告「8 个 agent 共享 default 工作区，一人调用全家漂移」。

**当前状态**：❌ **缺失**。

### 6.1 `chain` 链条传导（**15 号称它「最重要」**）

**完整规格**（原文）：
```
{operation:'chain',
 stages:[
   {name:'坑口价', expr:'raw'},              // 起始值
   {name:'运输成本', expr:'raw*0.3'},        // 每段一个表达式（可引用 raw 或前段）
   {name:'到岸价', expr:'prev+trans'},       // 支持引用前段
   {name:'合理利润', expr:'prev*0.25'},
   {name:'售价', expr:'prev'}
 ],
 raw: 8}                                    // 起始值（先令/吨）

→ {table:[{stage,value,delta,share}],
   total:'8 → 10.4 → 13.5 → 16.9（先令/吨）',
   breakpoints:['运输成本占总价 30%——若超过 50%，廉价性不成立'],
   verdict:'链闭合；运输段是主导成本'}
```

**为什么最重要**（原文）：「AI 自己在第 34 轮说『不是单一航速数字，而是一条链』。
价格链 5 层、时间链 7 段——**这是推演最核心的运算形状**」。

**验收标准**：用南极煤田第 47 轮的实际链条跑一遍，输出的表能对齐 AI 当时的结论。

**当前状态**：❌ **缺失**（`derivation sensitivity` 只做单点）

---

**为什么**：AI 推演时要「锚定真实历史数据」，但每次都要搜 23 个网页。

**当前状态**：❌ **缺失**

### 6.5 `threshold` 自定义阈值判断

**为什么**：AI 常写「若超过 50% 则…」，但没有工具帮它判落在哪档。

**当前状态**：❌ **缺失**（`quick_feasible` 部分覆盖判定，但不可自定义阈值）

# 六、`17`/`18` 号的两大类（设计文档）

## `17` 号：通用实体台账模型

**核心命题**（原文）：
> 任何「有内部结构、且结构要自洽」的东西，都可以用「节点 + 边 + 属性 + 规则」表达。

**十类实体**：地理 / 建筑载具 / 组织 / 生物 / 技术 / 经济 / 时间线 / 军事 / 装备 / 人物

**七种边**：`contains` / `adjacent` / `connected` / `depends` / `inherits` / `memberOf` / `before`

**七条通用规则**：闭合 / 对称 / 无环 / 可达 / 容量 / 连续性 / 一致性

**当前状态**：❌ **一行未实现**（`hierarchy` 和 `dependency` 只是它的两个特例）

## `18` 号：几何与地形模型

**核心要求**：
```
坐标系三种：平面笛卡尔 / 球面经纬度 / 区域图
能算：距离 / 坡度 / 遮蔽 / 可达性 / 行军天数
不出图：几何数据要存，几何运算要做，但图像不生成
```

**当前状态**：❌ **一行未实现**
