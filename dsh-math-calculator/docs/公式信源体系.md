# 公式信源体系（2026-11-13）

> 用户指示（2026-11-13）：**公式库的补充不去代码的开源社区，去科学的相关网站、
> 包括文献、科普等一系列权威信源收录公式，建立体系。**

这份文档回答三件事：**从哪收**（信源分级与可达性）、**怎么收**（采集规范）、
**收什么**（体系骨架与缺口）。公式本身不进这份文档，进 `src/data/formulas.json`。

---

## 一、原则

1. **公式内容以权威信源为准**，不以代码仓库里的实现为准（代码只作交叉验证）。
2. **每条公式必须有来源**：文献名/章节 + URL + 访问日期 + 许可。
3. **来源等级决定可信度标签**：标准/官方数据 → 精确；教科书 → 标度；科普 → 量级。
4. **不编造**：抓不到的页面标注「不可达/需人工核对」，不假装读过。

## 四、采集规范（每条公式的字段）

```jsonc
{
  "id": "planck_law",                       // snake_case，全库唯一
  "cat": "physics/quantum",                 // 105 类体系中的一类
  "name": "普朗克黑体辐射谱",
  "expr": "2*h*c^2/(lambda^5*(exp(h*c/(lambda*k*T))-1))",  // mathjs 可解析
  "params": { "T": {"value": 5778, "desc": "温度 K"}, ... },
  "unit": "W/(m^3·sr)",                     // 结果单位；无量纲写「无量纲」
  "desc": "含义 + 适用域 + 常见误用",        // 必须写适用域
  "keys": ["黑体", "普朗克", "planck"],
  "sources": [
    {
      "type": "textbook",
      "title": "University Physics Volume 3",
      "authors": "Moebs, Ling, Sanny",
      "publisher": "OpenStax",
      "chapter": "第 6 章",
      "url": "https://openstax.org/books/university-physics-volume-3",
      "license": "CC BY 4.0",
      "accessed": "2026-11-13"
    }
  ],
  "confidence": "exact"                     // exact | scaling | order-of-magnitude
}
```

**硬规则**：新公式 `sources` 不得为空；`expr` 必须过 mathjs parse；
展示式必须标 `executable:false`；参数 `desc` 必须带单位。

## 八、公式即函数与关系图（2026-11-13）

### 8.1 公式变成可执行函数

`src/features/formulas/function.ts`：

```
compileFormula(entry, engine, index?) → FormulaFunction
  { id, name, unit, params:[{name, required, default, desc}], call(values, options) }
callFormula(formulas, idOrName, engine, values, index?, options?)
```

- **参数契约**：必填（value=null）与可选（默认值）分开；缺参报 `missing_params` 并列出该给哪些；
- **调用结果**：`{ result, value, substituted, missing, neighbors, notice }`；
- 计算逻辑仍只有一份（`evaluateFormula`），本模块只做契约与关系。

### 8.2 关系图（共用物理量 / 常数 / 共性）

`src/features/formulas/relations.ts`：740 条公式、**17,493 条边**、44 个常数名。

| 边的来源 | 权重 | 说明 |
|---|---:|---|
| 共用参数 | ×2 | 同名参数（m、T、v、rho…） |
| 共用常数 | ×1 | 参数名本身是常数（k、h、c、G、R…） |
| 同类别 / 同标签 | ×0.5 | cat 相同或 keys 有交集 |

构建用倒排索引（参数名 → 公式集合），不做 740×740 两两比较；结果按 id 缓存。

### 8.3 调用时看见相邻公式

- `{operation:"formula", formula:"ideal_gas", params:{n:1,T:300}}`
  → `value.neighbors`（前 6 条，带共用参数/常数/理由）+ `notice` 一行摘要；
- `{operation:"formulas", query:"neighbors", formulaFocus:"ideal_gas"}`
  → 列出前 10 条相邻公式与理由。

### 8.4 一个关键坑：常数别名

常数表把玻尔兹曼常数记作 `kB`，而公式库惯写 `k`。不补别名时 `k` 被当成
「共用参数」，「共用常数」这条边就丢了——关系图少一整类联系。
现已在 `constantNames()` 补 `k` / `mu_0` / `epsilon_0`。

### 8.5 已知限制（有意保守）

**同名参数不等于同义**：`m` 可能是质量也可能是摩尔浓度，`n` 可能是物质的量
也可能是复利期数。所以边只声明「用了同一个符号」，理由里把符号名列出来，
由调用方判断语义。宁可少连，不可乱连。
