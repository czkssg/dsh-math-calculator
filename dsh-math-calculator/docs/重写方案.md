# 二、「保留设计」的准确含义

## 2.1 保留（设计资产）

| 资产 | 数量 | 为什么不重写 |
|---|---|---|
| **公式定义** | **665 条** | 每条都经过「参数/表达式/适用域/关键词」手工校对，是本项目最大资产 |
| **推演链** | 22 条 / 333 项 | 公式之间怎么连，是领域知识 |
| **单位表** | 464 条 + 别名 | 含 462 条中文古制单位，开源库里没有 |
| **天体目录** | 26 个 / 32 类 | 真实数据 |
| **常数依赖图** | 43 个节点 | 手工校验过派生关系 |
| **可信度标签体系** | 4 级 + 适用域 | 项目的立身之本 |
| **help 正文** | 48 节 3,045 行 | 每条都写了「为什么这样」与踩过的坑 |
| **测试断言** | 6,742 项 | 它们定义了「什么算对」 |

## 2.2 不保留（代码）

| 资产 | 行数 | 为什么重写 |
|---|---|---|
| 全部 TypeScript 实现 | 60,339 | 用户要求 |
| 125 个源文件的结构 | — | 结构本身有问题（`index.ts` 5,721 行 62 函数） |
| 手写算法 | ~1,000 | 换成开源（含 ml-matrix / jstat / graphology / Turf） |

**关键判断**：数据与设计保留为**独立的数据文件**，新代码只负责读取与计算。
这样「数据」与「逻辑」彻底分离 —— 而老代码把他们混在 `.ts` 里。

## 3.2 `ucum-lhc` 许可核实结果（这是重写前必须确认的）

```
The following terms and conditions are based on the BSD open-source license.

Redistribution and use in source and binary forms, with or without modification,
are permitted for commercial and non-commercial purposes and products alike,
```

**结论：可以安全用于 MIT 项目**（BSD 兼容，仅需保留版权声明）。
另有署名要求：「If publishing research that used this software, please include a citation」。

**这条解决了老规划里「许可待核实」的悬念**。

## 4.1 三个结构性改变

**① 数据与逻辑分离**

老代码：665 条公式写在 27 个 `.ts` 文件里（13,049 行），与检索逻辑混在一起。
新代码：`data/formulas.json` 纯数据，`features/formulas/` 纯逻辑。

**② `index.ts` 从 5,721 行降到 < 100 行**

老代码：62 个函数 + 40 个 case 分发全在一个文件。
新代码：`dispatch.ts` 做路由表，每个 operation 在自己目录里。

**③ 五个功能域各自独立目录**

老代码：按「文件类型」组织（`world.ts` / `climate.ts` / `terrain.ts` 平铺在 src/）。
新代码：按「功能域」组织，领域内文件放一起。
