# 更新日志

本项目遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 与 [语义化版本](https://semver.org/lang/zh-CN/)。

## [2.1.0] — 2026-10-28

公式库扩到 404 条、新增天体目录与类型学、工具定义瘦身 21%，并把「计算精度」与
「显示精度」彻底分开。全部改动都有测试守（77 套 / 3717 项）。

### 新增

- **天体目录 \`bodies\`**（第 30 个 operation）：26 个具名天体
  （太阳系 8 大行星 + 木卫二/土卫六/土卫二 + 谷神星/冥王星 + 5 颗系外行星 + 7 颗各亮度级恒星）
  与 **32 类天体类型学**（白矮星、中子星、黑洞、褐矮星、热木星、流浪行星、戴森球…）。
  每个数值带**依赖标记**：物理必然 / 随常数变 / 地球标定 / 历史偶然。
- **常数传导**：\`bodyConstant + bodyFactor\` 回答「改了 α 或 G，天体数据哪些该重算」。
  分三块：有幂次的（化学键能 ∝ α²）、**间接依赖**（行星平衡温度，要重跑）、
  **绝不该动**（行星质量/半径/轨道 —— 改了就是篡改设定）。
- **公式库 395 → 404**（第八批 \`formula-library-generic.ts\`）：
  把烘焙进系数的常数剥出来，换成可换参数的普适形式。
- **经验公式拆解**：每条经验式标注三级适用域 ——
  无量纲通用（克莱伯 0.75）/ 形式可泛化但系数需重验（Fr≈0.4）/ **仅地球成立**
  （Mifflin 代谢、风寒、Du Bois 表面积等 7 条）。用旧公式时输出会附「藏了什么、何时失效」。
- **结果缓存**：键含常数与工作区指纹，改常数后必然失效。
- **批量求值**：\`expressions\` 一次算最多 100 条，逐条独立报错。
- **计算需求三档分流**：simple（不提醒）/ forced（提醒）/ fuzzy（按阈值），
  不调用 LLM，成本近零。补上中文数字、工程语境（城墙厚度、射程、划桨）识别。
- **显示精度可调**：默认 **8 位小数**，\`displayPrecision\` 单次覆盖或工作区固化。
- **精度不足主动提醒**：按**相对误差**判断（阈值万分之一），
  \`0.00000123456789\` 在 8 位下误差 0.37% 会提示「请传 displayPrecision:16」。

### 变更

- **\`displayPrecision\` 语义从「有效数字」改为「小数点后几位」**。
  旧语义下 \`12345.678901234\` 只给 3 位小数（12345.679），与「保留 8 位」的直觉不符；
  现在给 12345.67890123。\`formatValue\` 与 \`trimNumber\` 同步。
- **默认显示精度 64 位 → 8 位小数**。整数永远完整（\`10^20+5\` 仍 21 位）。
- **工具定义瘦身**：7789 → 6140 字符（省 21%，约 1100 token/轮）。
  \`world\`/\`terrain\`/\`constants\` 等字段表移进 \`help\`，**参数一个没删**。
  \`description\` 不再重复枚举 operation（\`enum\` 已列全）。
- **恒星假设显式声明**：未给恒星参数时声明「已默认太阳」；给了模型不支持的光谱型
  （如 \`F5III\` 巨星）时在输出**最前面**警告「只支持主序星，结论不能直接采信」。
- **rust 提示词**：不再写死「3—4 位有效数字」，改为「保留几位由你判断」。

### 修复

- **检索修复从未生效**：\`index.ts\` 里有一份 \`findFormulas\` 旧副本，
  \`formulas\` 操作调的是副本 —— 工具里查「贷款月供」0 条，而单元测试全绿。
  抽出 \`scoreFormulas\` 作唯一实现。
- **模糊匹配污染公式求值**：\`'完全不存在的公式xyz'\` 因二字词「公式」命中别的公式，
  报 \`missing_params\` 而非 \`unknown_formula\`，模型会去补一堆无关参数。
  拆成「检索用模糊、求值用严格」。
- **缓存键串键**（两次）：① 手动列举参数漏掉 \`distribution\`/\`params\`，
  二项 PMF 返回了正态 PDF；② 显式与默认同为 8 时撞键，显式调用继承了
  「精度不足」提示。现改为全量 args 序列化 + 显式标记入键。
- **状态变更必须清缓存**：覆盖/移除公式后仍命中旧值（\`kinetic_energy\` 覆盖得 18，
  移除后仍 18，正确答案 9）。
- **极小值显示成 0**：\`3.3e-9\` 在 8 位小数下 \`toFixed\` 得 \`"0.00000000"\`，
  转回数字变 \`0\` —— 非零值显示成零属数据丢失。现凡会被舍入到 0 的一律用科学计数法。
- **高精度显示丢位**：\`precision:30\` 只给 16 位（BigNumber 先转 Number 丢掉精度）。
  现高精度路径直接用 BigNumber 格式化，并裁掉尾随零。
- **\`1/1234567\` 显示成 \`8.1e-7\`**：数值对但看着像只有两位有效数字。
  改用文本去尾随零，得 \`0.00000081\`。
- **提示污染数据通道**：把提示拼进 \`result\` 使 \`0.1+0.2\` 从 \`0.3\` 变成两行，
  一次跑挂 8 个套件。提示改走独立 \`notice\` 字段，只由渲染层展示。
- **「只提示一次」破坏确定性**：同输入连调两次输出不再字节一致。
  改为确定性判断（未固化 + 有小数 → 每次都带）。
- **列表编号误伤小数**：\`1.5倍\` 里的 \`1.\` 被当列表编号，压低物理推演场景得分。
- **序数误判为数量**：\`第三纪\`/\`第 3 次\` 让编年史文本误报计算需求。

### 已知局限

- 分流靠**词表匹配**，不是语义理解。\`洋流方向对港口结冰的影响\` 这类
  既无数量也无疑问词的陈述型问题仍不提醒（可能是漏报，也可能是合理）。
  继续加词表会推高误报风险，当前取舍是「0 误报优先」。
- 缓存是进程内 Map（上限 256 条，LRU），不跨会话持久化。

## [2.0.0] — 2026-10-26

首个公开发布版本。

### 新增

- **公式库 355 → 395 条**，补的是**通用计算**（第七批 `formula-library-basic.ts`）。
  起因是实测：35 个常见计算需求只命中 17 个，缺的全在金融/几何/化学/电学/工程：
  - 金融 10 条：等额本息月供、单利、年金现值、NPV、直线折旧、盈亏平衡销量、
    实际年利率、复利翻倍时间、通胀后购买力、毛利率
  - 几何 8 条：余弦定理、正弦定理、扇形面积、球冠体积、梯形、椭圆、圆环体、正多边形
  - 化学 8 条：溶度积、滴定体积、质量摩尔浓度、质量百分比、ppm、标准气体体积、
    摩尔数换粒子数、放射性剩余量
  - 电学 7 条：容抗、感抗、LC 谐振、分压、用电量、电池续航、变压器匝数
  - 工程 6 条：齿轮比、雷诺数、热应力、弹簧储能、液压推力、皮带轮转速比
  - 天文 1 条：主序星寿命（此前只在 `world` 内部算，没暴露成公式）

  这批全部做了数值验算，且尽量带**可自证的端点**：余弦定理在 3-4-5 直角三角形
  上应得 5；球冠 h=r 得半球 2π/3、h=2r 得整球 4π/3；正多边形 n=4,s=2 得正方形面积 4；
  单利与年复利在 t=1 时必须相等。

### 修复

- **检索查不到中文复合词**（比补公式更影响体感）：`findFormulas` 只做整串子串匹配，
  于是 `粮食` 能查到 4 条、`粮食产量` 却是 0 条；`比热` 能查到、`比热容` 查不到。
  用户和 AI 不会总说最短形式。现在加了：
  - 中文 2—4 字滑窗子词匹配（`粮食产量` 能对上关键词「粮食」「产量」）
  - 同义词表（`比热容`→`比热`、`月供`→`贷款`、`粘度`→`黏度` 等 30 组）
  - 词元按长度加权，长词命中排前面，避免「粮食产量」把所有含「量」的公式挤上来
  - 默认返回上限 10 → 20（宽查询不再被截断）

- **`world` 顶层参数静默失效**：此前只认 4 个便捷参数
  （`planetRadius`/`planetMass`/`rotationHours`/`obliquityDeg`），
  于是 `{operation:'world', starMass:10}` 里的 `starMass` 被**静默丢弃** ——
  输出仍是太阳（主序寿命 10 Gyr），一句报错都没有。作者以为算的是 10 倍质量恒星。
  现在改为遍历 `WORLD_PARAMS` 全量白名单派生便捷参数，且 `world` 内同名键优先。

- **频次测试写死绝对值**：`formula-story.mjs` 断言「高频 50—130 条」，
  公式库一扩容就误报失败。它本意是「高频不应占满全库」的比例约束，
  改成占 20%—60% 的比例断言。

### 修复

- **主动提醒命中率归零**（最严重的一条）：`agent/pre-step` 钩子用
  `content.includes('math_execute')` 判断「本会话是否已用过插件」，而我们的系统提示
  每轮都注入、且必然包含这个词 —— 于是 `toolUsedInSession` 恒为 `true`，
  检测器从第一轮之后**永久静默**。

  实测：检测器本身命中率 72%（13/18 条真实作者语句，误报 0/6），但经过钩子后
  实际命中率 **0**。修法是改成**结构化判断**：只看 `role === 'tool'` 消息、
  assistant 的 `tool_calls` 数组、或 content 里的 `type: 'tool_use'` 块。
  「用户问 math_execute 怎么用」也不再被误判成「已用过」。

  修后实测：真实对话历史（含系统提示）下命中率 **90%**（9/10），
  真调过工具后仍正确静默（4/4）。

- **工具描述漏了 3 个 operation**：`TOOL_DESCRIPTION` 里没有 `derivation`、
  `custom`、`feasibility`，模型因此不知道它们存在 —— 而所有测试全绿。
  原因是 `test/awareness.mjs` 里手写了一份 operation 清单，加新 op 时没同步。
  现在清单**从 schema enum 派生**（唯一真相），并加反向断言与长度预算（≤900 字符）。
  描述长度 810 → 718 字符，同时覆盖全部 29 个 operation。

- **检测器缺势力收支类词表**：`balance` 是新增能力，但检测器词表里没有
  「养得起/够不够/军费/粮草」这类说法，导致「这个王国养得起二十万兵吗」评分 0。
  已补两条意图模式，命中率 72% → 83%。

- **`help` 让作者去点一个不存在的面板**：数据管理那段还写着「侧栏『数学工作区』入口
  可图形化管理」，但界面 2026-10-25 已全部移除。AI 照读会把作者引到一个点不开的入口。
  已改成「本插件没有图形界面，全部经工具与 HTTP 路由操作」。
  同时 `test/advanced.mjs` 里那条「help 必须提到侧栏入口」的断言原本把错误行为
  写成了预期，改为反向断言（不许出现「侧栏」，必须说明「没有图形界面」）。

- **世界推演的措辞违反项目铁律**：1.4 g 以上会输出「生物**必须**更矮壮」，
  而铁律要求输出措辞不出现「错误/禁止/必须」（`test/ai-brief.mjs` 守着这条）。
  改成「生物得长成矮壮型才撑得住」。这一条是**实际使用验收**跑出来的，
  原来的世界推演测试只看数值不看措辞。

- **单位清单的伪精度**：`亩` 的系数是 666.6…（无限循环），清单里显示成
  `666.6666666666666`，看着像精确值。系数改用独立格式化，显示 `666.667`。

### 测试

- 新增 `test/real-usage.mjs`（94 项）：**作者视角的实际使用验收**。
  与其它套件不同，它验的是「拿去能不能用」而不是「算得对不对」：
  输出里不许出现已删界面、`Infinity`/`NaN`/`undefined`/`[object Object]`；
  必须有单位与可信度标签；措辞不许反驳作者设定；错误必须给修复方向；
  输出体积有上限（AI 读得下）；并把「1.5 g 星球 → 50 米巨兽站不住 →
  300 米塔能建 → 王国养不养得起兵 → 火箭飞不出去 → 三十里多长」串成一个
  完整场景，检查前后自洽。

### 移除

- **UI 全部移除**（2026-10-25，`14f6ed0`）。做了三版（目录树 18 节点 → 精简 10 节点 →
  单页工作台）效果始终不好，决定砍掉：`src/client.ts`（2497 行）、`lib/client.js`
  （138.8 KB）、9 个客户端测试套件、`tsconfig.client.json`、`package.json` 的
  `dsh.client` 与 `exports["./client"]`。**后端模块一个没动**，能力全部保留，
  只经 `math_execute`（27 种 operation）与 HTTP 路由给 AI。见 `docs/ui-removed.md`。

### 新增

- **世界参数校验（三档）**：`world-params.ts` 的 `range` 此前是**纯装饰** ——
  22 处声明没有任何代码读取，实测 `planetMass=-5`、`planetRadius=0`、`albedo=5`
  都 200 OK 存进去了。新增 `src/world-validation.ts` 让范围真正生效：
  - **硬拒绝 400**：`range.hard` 且**低于下界** —— 会算出无穷/非数/负物理量
    （零半径 → 重力 Infinity、零质量 → 离心比 Infinity、零轨道 → 80 处 Infinity）；
  - **软警告 200 + `warnings[]`**：越界但仍照设定算（`planetMass=500`、`albedo=1.5`），
    消息里给出范围与代价。**上界一律走这一档** —— 「质量大得离谱」是设定自由，
    拦了就违反「不反驳用户设定」；
  - **静默接受**：在范围内。

  哪些参数标 `hard` 是**实测**出来的（逐个取极端值跑推演、统计产物里 `Infinity`/`NaN`
  个数），不是拍的。实测还暴露了探针自身的 bug：`planet.surfaceGravity` 其实是
  显示串（`'Infinity'` 字符串），只看 `typeof === 'number'` 会整片漏判。

- **`invalid` 判定档**（`dead-universe.ts`）：检出物理量非有限/为负时判 `invalid`，
  与 `dead` 分开 —— `dead` 是「死寂宇宙」这种合法设定，`invalid` 是「参数本身算不出数」。
  混在一起会让作者以为「世界设得太狠」，实际是把半径写成了 0。渲染措辞仍只讲怎么改，
  不写「错误/禁止/必须」。

- **逐颗卫星 `moons` 可存档**：`world.ts` 早已支持 `MoonSpec[]`（洛希极限/希尔球/
  相邻间距/观感），但 `moons` 不在白名单里，导致「多卫星系统」只能直接调 tool、
  存不进工作区。`ParamSpec.kind` 新增 `'array'` 与 `itemShape`，现在能存能校验。

### 修复

- **`Infinity`/`NaN` 会流到 AI**（最伤可信度的一条）：`/summary` 的
  `derived[].value` 曾是裸 `Infinity`（只有 `text` 被格式化成 `—`），
  `verdict.causes` 里也有 `"表面重力不成立：Infinity m/s²"`。AI 会当成真数字写进结语
  ——「这颗星球重力是 Infinity」。现在 `deriveAll` 用 `finite()` 统一归一化，
  `judgeDead` 的原因描述改成中文（不出现字面量），整个响应不含 `Infinity`。
- **`save-world` 的双白名单事故**：该路由曾自带一份 14 键硬编码白名单，
  而 `WORLD_PARAMS` 有 23 个基础量 —— 于是 `starClass`（「我要 G2V 恒星」）、
  `hasLiquid`、`materialStrength/Density`、`moonCount/Mass/Distance`、
  `lightPollution`、`galaxyBand` 共 9 个键被**静默丢弃**：返回 200 OK，不报错不提示。
  现在白名单只留一个真相。
- **类型静默强转**：`Number(true)===1`、`Number([])===0`、`Number(['7'])===7` ——
  `{planetMass:true}` 曾静默存成 1。现在只接受 `number` 与数字字符串，其余 400。
- **注入给 AI 的 operation 数量是旧的**：`awareness.ts` 的系统提示写「共 25 个」，
  实际 27 个（漏了 `derivation` 与 `custom`）。`integration.mjs` 的断言清单同样只有 25 个，
  现在补齐到 27 并加了**反向断言**（schema 里不许有清单外的名字）。
- **`npm run preflight` 因 UI 移除而崩溃**：它仍在 `readFileSync('lib/client.js')`，
  文件已删 → `ENOENT`，装机前自检直接非零退出。改为反向断言（客户端产物确实不存在、
  无 `dsh.client`、无 `exports["./client"]`、无 `tsconfig.client.json`），
  与 `test/integration.mjs` 第 5 节互为印证。
- **`tsconfig.json` 仍排除 `src/client.ts`**：文件早不存在，排除项清掉。

## [2.0.0] — 2026-10-24（内部定稿，未发布）

> 这是公开发布前的内部定稿，内容并入上方 2.0.0 一起发布。

### 能力

- **计算内核**：BigNumber 64 位高精度求值、符号微积分（求导/积分/化简/展开）、
  解方程与线性系统、矩阵（秩/行列式/迹/奇异值/零空间/逆）、统计与概率分布、
  回归、ODE（RK4）。
- **UI（令牌化）**：左栏「全局管理」与右栏「本工作区工作台」共用同一套宿主设计令牌
  （`--dsw-alias-*` / `--dsw-font-*` / `--dsw-radius-*`），无写死颜色；
  **新建工作区即生成同名数据表**（`<工作区名>.json`，含常数/公式/地点/变量四张子表），
  切换工作区后右栏自动跟随。
- **公式库 342 条**，每条带**三轴标签**：
  `layer`（离最底层规则的远近：基本/数学/导出/经验/工程/约定）、
  `domains`（学科领域，多标签）、`frequency`（**主角视角感知频率**）。
  检索：`freq:` / `layer:` / `domain:` / `symbol:` / `keyword`。
- **两级公式扩展**：全局公式包（`$DSH_HOME/math-calc/formula-packs/global.json`，写盘即生效）
  + 工作区临时公式；新增时校验 id、表达式可解析、**符号必须已定义**（拼错变量当场拒绝）。
- **符号消歧**：同一字母不同含义（`m` = 质量/米）可查 `symbol:m@质量`。
- **常数推演**：无量纲优先（α/μ/α_s/α_G）、尺度阶梯、单位旋钮与物理改动分离、矛盾清单。
- **世界推演**：恒星（质光/寿命/宜居带/α 敏感度）→ 气候 → 天空配色 → 卫星系统 →
  化学窗口与生命硬否决 → 跨模块一致性检查 → 经验系数可信度标注。
- **UI**：左侧入口 = **全局管理**（所有工作区：创建/切换/删除，常数表、公式表、设置）；
  右侧边栏页签 = **本工作区工作台** —— 工作区切换器、本区数据表（常数/公式/地点/变量）、
  **开关**（提示档位、公式启停）、**管理**（变量与地点的增删）。
  左栏切换工作区后右栏**自动跟随**（同一 client bundle 内的订阅 + 宿主 `sidebarRight` store）。

### 工程质量

- 全量 **41 套 / 1716 项**测试；含确定性、真机宿主契约、**对抗性兼容性**（敌意 ctx、
  服务抢占、全局污染、数据损坏）与**客户端注册契约**回归。
- `preflight` 装机前自检：入口契约、客户端席位、运行期依赖、注释覆盖、清单一致性、
  peer 版本可接受性。
- `doccheck` 强制：每个模块有头注释、每条导出有文档注释（321 导出 / 0 缺失）。

### 修复（相对内部早期版本）

- **客户端注册 id 必须等于包名**：此前用 `<包名>-client`，宿主按包名查找不到模块，
  导致桌面端每次启动都报 `import failed` 并致命退出。
- **客户端入口幂等**：宿主会重放 bundle，重复注册会抛错并升级为致命错误。
- **peer 依赖接受 prerelease**：`>=0.1.0 <0.3.0` 不接受 `0.1.7-rc.2`，改为 `>=0.1.0-0 <0.3.0`。
- **工作区切换自动落盘**：此前切到不存在的工作区只产生内存对象，`current` 会指向幽灵工作区。
- 工作区创建兼容 `name` 参数（此前只认 `workspace`，误报「不能是 default」）。
