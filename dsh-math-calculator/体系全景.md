## 一、这套体系是什么

513 条公式按 `cat` 分成 73 个分类，但**分类不等于链条**：

```
  engineering/thermal 里有 boiler_coal_rate、steam_power_output、carnot
  但它们之间没有登记「谁的输出喂给谁的输入」
  使用者拿到 5 条公式，仍然不知道先算哪个、结果怎么往下传
```

所以登记三层：

| 层 | 字段 | 作用 |
|---|---|---|
| 体系 | `FORMULA_SYSTEMS` | 一条推演链，含 `purpose`（什么时候想起它）|
| 步间连线 | `steps[].feeds` | 上一步的输出喂进本步的哪个参数 |
| 体系间接点 | `bridges` | 某公式同时属于几条链 |

### 查法（三种，都是 `formulas` 的 query）

```
  formulas query="sys"                    → 18 条链清单与 purpose
  formulas query="sys:sys-energy"         → 能源链逐步（公式/输出单位/需自备参数）
  formulas query="sys:formula:metallurgy" → 属于哪几条链 + 接点说明
```

## 二、为什么不是一个大体系

「能连的尽量连」不等于「全部串成一条」。真实推演里：

```
  算一座窑   → 能源链（燃料→热量→时间）—— 不需要人口与财政
  算一个文明 → 食物链+人口链+财政链 —— 也不需要窑的具体热损
```

硬串成一条会让每一步都拖上无关参数。所以按**推演目的**分体系，
体系之间只登记真实存在的共用公式。

### 3. 能源链（燃料 → 热量 → 时间 → 能耗）

### 4. 产能链（矿 → 金属 → 工时 → 年产量）

## 六、跨链多跳路径（体系真正的用处）

单条链只能算「一步接一步」。真正难的问题是跨 3~4 条链的推演，
下面是从图上实测出来的真实路径（最短，不是凑的）：

### `sys-astronomy` → `sys-fiscal`（4 跳）

*一颗星的光度，怎么一路推到财政能不能撑住*

1. `sys-astronomy` → `sys-climate`　via `inverse_square_flux`
2. `sys-climate` → `sys-energy`　via `heat_conduction_slab`
3. `sys-energy` → `sys-capacity`　via `thermal_efficiency_carnot`
4. `sys-capacity` → `sys-fiscal`　via `gdp_from_labor`

*水渠容量，怎么推到这支军队打不打得起*

2. `sys-food` → `sys-fiscal`　via `population_fed_by_grain`
3. `sys-fiscal` → `sys-military`　via `fiscal_burden_ratio`（对方链声明）

### `sys-material` → `sys-food`（2 跳）

*材料工艺，怎么推到能养多少人*

1. `sys-material` → `sys-capacity`　via `metallurgy_yield`
2. `sys-capacity` → `sys-food`　via `labor_force`

### `sys-info` → `sys-capacity`（2 跳）

## 七、覆盖率

| 指标 | 值 |
|---|---|
| 公式总数 | 607 |
| 入链公式数 | 191（31.5%）|
| 线上公式总数（本文件可见部分）| 191 |

**覆盖率不是越高越好。** 几何公式（正余弦定理）、电池续航、
回声测距这类确实没有上下游 —— 为刷覆盖率硬塞进去，
造出假关系比保持孤立更糟。

`error_propagation` 是**故意不归链**的：它服务于所有计算，
挂到某一条链上反而误导。测试里有断言守着这个决定。
